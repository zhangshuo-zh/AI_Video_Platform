# 生产依赖：三行就够，但**每一条都要有上界**。
#
# 为什么必须有上界（2026-11-08）：原来只有 `>=`。换个时间装机就可能得到
# 另一个 fastapi / pydantic 大版本——这个项目里 `models.py` 有 121 个
# Pydantic BaseModel、26 个 `from_row()` classmethod，对 v1/v2 的行为差异
# 非常敏感（`Field(min_length=...)`、`model_dump()`、校验错误结构都变过）。
# 上界写在这里，等于把"我们只在验证过的这一代上跑"变成机器可读的事实。
#
# 为什么 `pydantic` 要显式写：它原来是**靠 fastapi 传递进来的**——本项目
# 直接 `from pydantic import BaseModel`（models.py 与 routers/auth.py），
# 属于直接依赖。传递依赖的版本不受我们控制，也不该由我们猜。
# 显式声明之后，`pip check` / 依赖冲突排查才有准确的那一行。
#

# 供应商密钥的密文存储（2026-11-11，用户批准新增）：AES-256-GCM。
#
# 为什么必须加这一条而不是自写：库里要存"能解密回明文"的供应商密钥，
# 标准库只有 hashlib/hmac（单向），没有对称加密。自写 AES/ChaCha 是
# 密码学上不可接受的（侧信道、padding、nonce 复用每一条都能致命），
# 所以只有"加一条经过审计的实现"与"不加密"两个选项。用户选了前者。
#
# 上界照旧：`<47` 是当前 46.x 这一代（AESGCM 接口自 3.1 起稳定）。
