# AI 视频生产平台

2–5 人局域网自部署的 AI 动漫／视频生产平台。后端 FastAPI + SQLite（WAL），
前端是原生 ES Module 静态页面（无构建链、不依赖 node），
生成作业由独立的 `worker.py` 进程执行（可多开，按资源类并发）。

- 文档类型：仓库门面与运行入口（怎么跑起来、怎么验、文档在哪）
- 版本：v1.2（2026-11-06），对应设计稿 v0.124

## 这是什么

一句话：把「小说 → 剧本 → 分镜 → 关键帧 → 视频 → 配音 → 成片 → 审核签字」
这条 AI 动漫生产线，做成一台机器上能自己跑的 Web 系统。

三条不肯让步的规矩，改代码前先读：

- **只有一个队列。** 所有生成作业进 `job` 表，由 `worker.py` 领取，没有第二条通道。
- **只有一个选路出处。** `services.resolve_provider()` 按默认轨走，不补位、不兜底，
  本地失败不会自动转云端。
- **规格住代码。** 参数范围、计价、出处住在 `app/backend/adapters.py` 的清单里，
  界面只登记实例、只读规格；密钥只存环境变量名，值永远不出后端。

v0.123 起再补一条同级别的：**只有一个签字入口。** 人工签字只住审核中心那一处；
智能体要落的写操作先变成待审批动作摆到那里，签过的才由 worker 的下一拍执行——
编排层不自建第二套状态、也不复制一份模型配置。

## 快速开始

要求：Python 3.12、Git（文档正文的版本历史依赖它）。macOS 与 Linux 均可；
模型运行时（FastMetal／mlx-video／mflux）不是跑平台的前提。

```bash
cd app
./run.sh            # 首次运行会创建 .venv 并装依赖
```

浏览器打开 <http://127.0.0.1:8000>。生成队列要另开一个终端：

```bash
cd app
./run.sh worker     # 独立进程；Ctrl+C 停
```

日常开发嫌开两个窗口麻烦，可以一次起两个：

```bash
cd app
./run.sh dev        # API + worker 一起起；dev 之后的参数只给 worker
```

`dev` 只是把两个进程在同一个终端里拉起来（worker 仍是独立进程，PID 分开记，
`./run.sh stop` 照样一起停）。它**不接受 `--reload`**：uvicorn 重载会起壳进程再
fork 工作进程，worker 挂在下面会变成没人认领的孤儿；要自动重载请分开跑。

默认全局并发 1、每类 1（仍是「一次只跑一条」）。要并行可再开一个终端，并显式声明上限：

```bash
./run.sh worker --max-global 2 --max-video 1 --max-compose 1
```

上限是**每个进程**的；多个 worker 通过 SQLite 原子领取，同一条作业只会被一个进程拿走。
「模型中心 · 运行监控」与「产线中心 · 整季」的 worker 面板默认只列在线进程，
离线历史点开才展开——一行＝一个进程，这是租约归属的要求，不是显示冗余。

**也可以在网页上改**（模型中心 · 运行监控 · 并发设置）：那一页会拿这台机器
**自己历史作业的实测内存峰值**算出"这套上限要多少、本机还剩多少"，结论为
「会溢出」时不许直接保存，要先勾一句「我知道有内存溢出风险」；判定为溢出还会
进顶栏告警（`concurrency_over_memory`），因为设置页平时没人打开，而 OOM 是
下一次领活就发生的事。命令行显式给的 `--max-global` **优先于**网页设置——
`./run.sh worker --max-global 2` 是当下对着这台机器下的指令，不该被一周前
在网页上设的旧值悄悄盖掉。

停止两者：`./run.sh stop`。

**也可以从网页启停 worker**（模型中心 · 运行监控 · worker 进程）：省掉开终端敲命令。
但要说清楚：**那是手动启停，不是守护进程**——API 重启不会带走它（它自成一个会话），
worker 自己崩了也**不会**自动拉起，发现队列不动就回那一页再点一次。启停与命令行
共用同一个 `data/run/worker.pid`，所以 `./run.sh stop` 照样管得到网页起的进程。

首次启动时库里没有用户，会建超级用户 `superadmin`：

- 设了 `FASTVIDEO_ADMIN_PASSWORD`：初始口令就是它；
- 没设：随机生成 16 位，**只在启动那一次打印到 stderr**。

两种情况第一次登录都会强制改密。口令值不要写进仓库、文档或提交记录。

对局域网开放：`FASTVIDEO_HOST=0.0.0.0 ./run.sh`（默认只监听 `127.0.0.1`）。

## 测试与门禁

```bash
cd app/backend
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

测试用 ASGI 进程内调用，不起端口；数据库、文件、稿件工作区、作业目录全部落在临时目录
（`tests/conftest.py` 在 import 前设置环境变量），不会污染 `data/`。
假适配器只在测试里开启（`FASTVIDEO_ALLOW_MOCK=1`）。

改完东西按这四道跑，CI（`.github/workflows/tests.yml`）跑的是同一批命令：

| 改了什么 | 跑什么 |
|---|---|
| 后端代码 | `pytest -q`；再 `python3 tools/make_release_baseline.py --check` |
| 前端 JS | `python3 tools/js_load_check.py`（模块能不能加载；模块数由脚本现数，本文件不写死，一个失败都不许留） |
| 界面行为 | `python3 tools/production_browser_check.py`、`tools/model_center_browser_check.py`、`tools/agents_browser_check.py`（各起库副本＋独立端口，不写开发库）；改了金额／单位显示另跑 `tools/money_format_check.py`（10 项：null 念「—」、小额留 4 位、千分位、币种从数据来、整季无币种不造假数） |
| 文档 | `python3 tools/doc_structure_check.py`（目录、锚点、跨册引用、修订记录格式、历史不丢、留档头部、图） |
| 清临时目录 | `python3 tools/_harness.py --prune`（收 `.pytest-tmp` 下历史残留的 `fv-*`／`fvtest-*`／`test_*` 等，`--dry-run` 先看、`--keep 前缀` 点名保留） |

三套真浏览器验收各建一个 50–110MB 的 Chromium profile，跑完由 `tools/_harness.py`
的退出清理自动删掉（`FASTVIDEO_KEEP_TMP=1` 可留着排查）。**历史遗留的那一堆**用
`--prune` 收一次——2026-11-07 实测收掉 1.6G／242 项。

真模型跑没跑过，界面上「生产可用」那一列与《发布基线》§2 的矩阵说话；
mock 只证明代码路径，不作为真实模型生产验证证据。

## 配置

全部走环境变量；代码里没有写死的路径、端口或密钥。

| 变量 | 默认 | 说明 |
|---|---|---|
| `FASTVIDEO_DB` | `app/backend/data/platform.db` | SQLite 库 |
| `FASTVIDEO_FILES` | `app/backend/data/files` | 上传的定妆图等 |
| `FASTVIDEO_WORKSPACE` | `app/backend/data/workspace` | 文档正文的 Git 工作区，可指向已有稿目录 |
| `FASTVIDEO_JOBS` | `app/backend/data/jobs` | 作业日志与产物 |
| `FASTVIDEO_HOST` / `FASTVIDEO_PORT` | `127.0.0.1` / `8000` | 监听地址 |
| `FASTVIDEO_ADMIN_PASSWORD` | 空（随机生成） | 首次建超级用户时的初始口令 |
| `FASTVIDEO_LOCK_MINUTES` | `15` | 文档编辑锁时长 |
| `FASTVIDEO_DOC_MAX_BYTES` | `1048576` | 单份正文上限 |
| `FASTVIDEO_SESSION_HOURS` | `12` | 登录会话有效期 |
| `FASTVIDEO_COMPOSE_INTERPOLATE` | 开 | 成片导出前的 RIFE 补帧；设 `0` 退回复制帧。开着而本地运行时不齐会**直接失败并点名**，不静默降级（口径见《系统设计说明书》§8.13） |
| `FASTVIDEO_CORS` | 空 | 前端换 nginx 托管时填来源，逗号分隔 |

模型 provider 的密钥**只从进程环境读**，库里只存"用哪个环境变量名"
（如 `DEEPSEEK_API_KEY`、`DASHSCOPE_API_KEY`），不存值，也不回显到接口、日志或错误消息。
示例一律用占位符：

```bash
export DEEPSEEK_API_KEY=YOUR_API_KEY
export ALIYUN_WAN_BASE_URL=https://your_workspace_id.cn-beijing.maas.aliyuncs.com
```

provider 与默认轨在「模型中心 · 引擎管理」的能力轨表里选，逐屏步骤见
《模型中心使用说明书》§3。新部署要自己选一次 provider，并在进程环境里提供对应密钥；
Wan 真实付费调用还需要带 Workspace 的 `ALIYUN_WAN_BASE_URL`。

## 数据与 Git

`app/backend/data/` 整个目录被忽略，不会进仓库：
里面有 `platform.db`（含用户口令哈希与会话）、稿件工作区、作业产物与日志。

- 小说／剧本正文的事实来源是工作区里的 Markdown 文件 + Git 提交；库里只有元数据。
- 每保存一次、或应用一次 AI 改写，就生成一次提交，提交身份是操作的人。
- 备份用脚本，不要只手拷数据库：

```bash
cd app/backend
.venv/bin/python backup.py create
.venv/bin/python backup.py verify <备份目录>
.venv/bin/python backup.py restore <备份目录> --yes
```

`create` 用 SQLite 自己的 `backup()`（WAL 下直接拷文件会漏已提交数据），
把库、上传文件、文档工作区、作业产物打成一个目录；
manifest 记 sha256、`integrity_check`、`foreign_key_check` 与逐表行数。
恢复必须先验证，且会自动留一份 `restore-safety-<stamp>`。备份是整目录快照，不是增量。

提交信息沿用「工作包 + 版本」的风格（例如 `v0.71：W11 文档 AI 操作——…`）。
推送前先确认 `pytest` 全绿；需要代理的网络给 git 命令临时加环境变量即可，
不要把代理或凭据写进仓库配置。

## 不做的事

当前明确不做：节点画布、自建常驻推理服务（v0.121 起平台**连**本机已有的服务型引擎，
如 Draw Things／Ollama，但不自带推理服务）、失败自动转云端、把密钥或口令写进提交。
产线这一版另有三条：不做并发与整季批量以外的编排扩展、
不允许模板里出现云端节点（云端要逐镜头确认计费，建 run 时直接 422）、
