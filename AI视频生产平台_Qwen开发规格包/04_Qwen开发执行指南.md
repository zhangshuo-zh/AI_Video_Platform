# 交给 Qwen 3.8 Flash 的开发执行指南

这份指南是执行约束；详细的产品行为见 `01_需求概要说明书.md`，分层/接口/状态见 `02_系统设计说明书.md`，字段见 `03_数据字典.md`。

## A. 目标

在现有 AI 视频生产平台代码库基础上，按本规格补齐所有四期功能；不能另起炉灶重写。最终产物应是可运行、可测试、可备份恢复的系统，而非只有 UI 或静态 demo。

## B. 规格优先级

遇到矛盾时按以下顺序处理：

1. 用户明确确认且在 `00_原始设计稿.md`“决策基线”里标记已定案的技术/产品约束（本地优先、云端仅国内、静态前端+FastAPI JSON API、SQLite WAL、Repository、CLI adapter、唯一队列/成本账/审核写入口等）。
2. 本规格三个文档中明确标记“必须/规范决策”的内容。
3. 已有代码、迁移与测试体现的现存行为：如与目标规格冲突，先记录差异，不允许直接覆盖重写。
4. `00_原始设计稿.md` 修订记录里“已实现/已实测”的描述只能作为待核对线索；必须在真实仓库中复查，不能把修订记录等同于当前代码证据。
5. 标记为“建议/待核实”的内容，需要先形成设计差异条目，再决定是否实现；不能自行将推断改写成“用户已经确认”。

## C. 开工前必须做的仓库盘点（先报告、再改代码）

### C1. 读取

- 仓库 README、`app/run.sh`、`app/backend/main.py`、`config.py`、`db.py`、所有 routers/repositories/services/access/ranks/bootstrap/migrate。
- 所有 `migrations/*.sql`、数据库初始化/种子权限、测试、前端 `index.html`、`css/app.css`、`js/app.js`、`api.js`、`store.js`、`router.js`、`modules.js`、`views/*.js`。
- 实际运行的命令行脚本入口、支持参数表、模型权重路径与许可证文件；不得猜 CLI 参数。

### C2. 先产出盘点文件

1. `CURRENT_ARCHITECTURE.md`：目录树和模块职责。
2. `CURRENT_SCHEMA.md`：通过迁移与 SQLite schema 提取真实表/列/默认值/唯一约束/外键/索引。
3. `CURRENT_API.md`：所有路由的 method、path、request/response、status、permission；可用 `/openapi.json`、路由代码和测试交叉确认。
4. `CURRENT_PERMISSIONS.md`：真实的 20 个权限点完整列表、三角色的真实映射、超级用户逻辑和每个端点守卫。
5. `CURRENT_UI.md`：现有导航、每个模块/子页、真实写入入口、加载/空/错误态、主题和响应式行为。
6. `SPEC_DIFF.md`：按需求 ID 列明 `done / partial / missing / conflict / verify`，每条都包含依据文件/测试和处理方式。
7. `MODEL_CAPABILITIES.md`：每条 CLI/API 实际支持什么能力/参数、模型文件是否存在、许可/价格/设备实测情况；未知处填 `UNKNOWN`，不得猜测。

完成盘点后，给出不超过 15 条的优先级实施计划；然后开始改动，无需等待用户额外确认所有细节，但任何与“已确认决策”冲突的地方必须保留并报告。

## D. 分支/工作方式

- 每个工作包尽可能独立，改动范围小；先写测试/迁移，再写业务与 UI。
- 不能清空数据库，不得修改已部署迁移文件；新增迁移按顺序编号、可重复启动、一个迁移一个事务。
- 不引入 React/Vue/Next.js、Node build chain、Temporal、外部队列或在线剪辑库。
- 不做虚假的进度条、假 API、假成本、虚构模型。未接入功能在 UI 明确标为尚未配置/未实现，而不是“成功”。
- 任何请求/数据库字段变更都同步改 Pydantic schema、Repository、API 测试、前端 API client 与数据字典。
- 除非得到明确授权，不要大规模重排/格式化既有源文件，避免上下文窗口或自动修改造成整文件损坏。

## E. 开发工作包（依赖与验收）

### W00 — 规格与现状盘点

- 优先级：P0；依赖：无。
- 交付：C2 所列盘点文件、SPEC_DIFF、执行顺序、回归基线。
- 验收：权限点/API/schema 均有从代码/迁移/测试来的证据；不把未核实功能列为已完成。

### W01 — 保住既有基础设施与回归测试

- 优先级：P0；依赖：W00。
- 核查并测试：登录/登出/强制改密、项目 CRUD/归档/批量、项目所有人/协作人、用户层级、Provider 十槽位、资产 CRUD/图片上传、项目打开排序、集状态、双主题。
- 修复回归不改变确认语义；测试 migration 最新版本、`PRAGMA foreign_key_check`、服务启动和 stop。
- 验收：旧测试通过；新增测试覆盖 W00 中识别的真实风险。

### W02 — 通用 UI 交互与错误一致性

- 优先级：P0；依赖：W00。
- 统一 API 错误处理、loading、表单错误、toast/inline message、空/错/加载态、危险确认弹窗与 Escape 行为。
- 保留现有主题 token、焦点环、减少动效；确保表格行动作不会触发整行点击，局部筛选不清空输入。
- 验收：真实浏览器测试核心交互；无 console error；关键页面在 1440×900 和 800px 宽视口检查。

### W03 — 项目中心封版

- 优先级：P0；依赖：W01/W02。
- 核查是否完整实现：在产/已归档/全部、标签+搜索叠加、最后打开排序、创建/编辑字段整体提交、协作人选择、项目摘要、归档恢复、批量操作、危险删除确认、当前项目回退规则。
- 补齐所有人转移所有权 UX/API，如已有 endpoint 则复用。
- 验收：批量逐项权限；所有人/协作人/管理员权限符合 PRD；隐藏/筛选行不能残留在 picked 集合；项目中心不创建集、不提供独立成本账。

### W04 — 资产中心封版

- 优先级：P0；依赖：W01/W02。
- 核查角色/场景/道具、全局/项目范围、重名、提示词、参考图、设定引用、删除/清理策略、镜头引用显示。
- 对上传执行文件签名与大小校验、路径安全检查；图片删除只能针对已登记路径；项目删除只清理登记文件。
- 验收：合法图成功，伪造 MIME/过大文件拒绝，路径穿越拒绝；删除不会误伤非平台文件。

### W05 — 文档文件/Git/锁/元数据

- 优先级：P0；依赖：W01。
- 先确认当前有无 doc metadata/文件编辑接口；没有才通过增量迁移补齐 `Doc` 元数据。正文不进 SQLite。
- 实现/封版正文读取/编辑、Git 版本和 diff、expected version 冲突检测、编辑锁及超时回收；路径必须限制在配置根目录。
- 验收：一次正文编辑/应用润色可以生成 Git commit；第二个编辑者不会静默覆盖；非法路径不可读写；Git 失败时能恢复或保留未应用结果。

### W06 — Provider 配置与 adapter 能力清单

- 优先级：P0/P1；依赖：W01。
- 保留模型设置已有 5 类能力 × local/cloud 槽位；完善密钥“已配置/未配置”、默认选路、provider health/模型可用参数展示。
- 从 CLI 参数或官方 API schema 实际读取能力，建立 adapter manifest；不得靠模型名猜运行时。
- 验收：密钥值不出现在 DB/API/UI/log；每个能力有单一有效默认；云端视频没有自动 fallback。

### W07 — Job/Task schema 与统一队列

- 优先级：P1；依赖：W01/W06。
- 盘点当前 `job/task` 是否已存在。不存在时新增迁移，不重复建语义同等表；定义 Task/Job 职责与状态映射。
- 实现持久 Job 队列、幂等键、参数/提示词快照、单本地 worker 独立进程、日志路径、重启恢复、取消/重试状态。
- API 创建 Job 必须快速返回 ID，生成执行不在 API 请求内。
- 验收：同一 idempotency key 不重复执行；一个本地任务运行时不会并发启动第二个；杀掉 worker 后任务不会永远挂在 running；重试新建 Job 且原记录保留。

### W08 — 生成中心 UI 与成本账

- 优先级：P1；依赖：W07。
- 队列表/过滤/详情抽屉/日志/产物/失败原因/重试/取消/参数模板；成本列表作为 Job 聚合；项目中心只读摘要。
- Job 存单位、数量、单价、金额、币种、定价快照、账单核对状态；用 Decimal/整数最小单位避免金额浮点误差。
- 验收：云端任务的预计成本需用户确认；失败不默认归零；多币种分别汇总；重试保留原成本；本地任务记录耗时和资源数据。

### W09 — 本地 adapter 端到端

- 优先级：P1；依赖：W07/W08。
- 按真实仓库与模型权重完成：FastMetal T2V、mlx-video I2V（符合实际支持能力的模型档）、mflux image。
- 适配器只起 CLI 子进程，返回规范化 Job 结果；所有命令参数使用数组调用，不走 `shell=True` 拼接字符串。
- 验收：从浏览器分镜选择 → Job 入队 → worker 执行 → 产物登记/可预览 → 成本/耗时记录的完整回路；至少一个可复现的成功基准。

### W10 — 国内云端 adapter 与显式授权

- 优先级：P1；依赖：W06/W07/W08。
- 接入经许可证、国内可用性、官方 API、价格和密钥方案核验的文本/视频 provider；使用配置的国内服务，不新增境外聚合。
- 单镜头选择 cloud 后显示 provider/model/计价单位/预计成本 + 明确确认；重试继承 original execution mode。
- 验收：默认本地任务不会触发云端调用；模拟本地失败也不会自动云端兜底；云端错误/请求 ID/实际用量有日志并脱敏。

### W11 — 文档创作与 AI 操作

- 优先级：P1；依赖：W05/W06/W07。
- 实现/封版小说/剧本/分镜文档树，AI 起草/扩写/续写/润色/剧本化/提示词等操作；所有实际模型调用用 Job。
- 默认 diff 预览 + 用户确认应用；写回后 Git commit；版本状态不能早于实际写文件成功。
- 验收：端到端执行“润色 → 比较 diff → 应用 → Git commit → 校验报告”；失败过程保留原文。

### W12 — 分镜表与资产引用

- 优先级：P1；依赖：W03/W04/W05/W11。
- 完整表格字段以当前 schema 映射为准；实现镜头编辑、资产 picker/chips、每镜头作业提交与状态只读展示。
- 不做节点画布。确认 shot 属于 episode 还是 doc 的关系后保持旧 API 向后兼容。
- 验收：引用资产只读、跳转资产中心；多个 Job 可对应一个镜头；修改 Shot 后不会改变已提交 Job 的输入快照。

### W13 — 文本抽取候选

- 优先级：P1；依赖：W05/W07/W11/W04。
- 依据已存在 `接口草案-抽取.md`（若在仓库中）核对现有 `extraction_run`、`extraction_item`、幂等规则和六个接口；没有时按草案增量实现。
- 候选必须绑定 Doc 版本与原文偏移，角色/场景/道具经过人工接受后才入 Asset；镜头候选只导出 Markdown。
- 验收：重复提交不产生重复资产；原文证据偏移与被冻结版本一致；抽取成本通过 Job 入账。

### W14 — 审核中心与校验器 gate

- 优先级：P1；依赖：W05/W07/W11/W12。
- 包装现有校验器 CLI，统一报告格式；实现审核队列、通过/驳回/退回、签字时间与签字身份、版本绑定。
- 唯一 Review 写入口在审核中心；其他页面只读状态。
- 验收：没有 reviewer 权限不能签字；文档版本变化后旧审核不能显示为新版本已通过；每句签字有稳定锚点。

### W15 — 音频中心与 TTS/音乐

- 优先级：P2；依赖：W07/W08/W11/W12。
- 音频中心组织台词/旁白/音乐/viseme；对 VoxCPM2 和 ACE-Step 分别建立 CLI adapter；音频中心不创建独立队列。
- 保存音频路径、时长、字级时间戳、说话人/镜头关联；Rhubarb 只用于合适的口型镜头。
- 验收：一集配音与音乐进入同一队列；产物关联对应镜头；成本只由 Job 记录；无法确认的环境音/音画同生标记实验态。

### W16 — 项目看板与素材导出

- 优先级：P2；依赖：W03/W07/W12/W14/W15。
- 汇总项目/集/镜头生成态、审核通过数、失败/待处理任务和成本摘要；所有数据从权威模块只读聚合。
- 可导出镜头清单/素材路径/状态给剪映/达芬奇或人工工作流，不做时间线编辑。
- 验收：统计与真实 DB/Job/Review 状态一致；看板没有第二份手工编辑状态。

### W17 — 许可与真机基准

- 优先级：P1（在启用任何具体模型前必须完成）；依赖：W06/W09/W10。
- 复核实际使用模型权重/版本的许可与 API 计价；在目标 Mac 上按设计稿 §7.6 执行模型基准；未知的数据标 UNKNOWN。
- 检查 H3/LTX 许可的标注、地域/营收条款是否适用于当前版本；建立模型禁用/停用流程。
- 验收：每个可见模型档都有可运行性/参数/许可/价格/实测记录；没有猜测的耗时或峰值。

### W18 — 稳定性、迁移、备份与发布

- 优先级：P0/P1/P2 都要持续做，最终发布前完结；依赖：W01–W17。
- 回归权限、项目隔离、文件清理、SQLite 迁移、worker 崩溃/重启、备份恢复、双主题、键盘和窄屏。
- 更新 README、环境变量说明、`run.sh` 启停 worker、数据目录说明与故障恢复指南。
- 验收：从旧数据库升级无丢数据；备份恢复后外键/文件/Git/Job 状态可用；所有功能 status 列表明确标出完成/未完成。

## F. 验收汇报格式

每个工作包完成后必须输出：

```text
工作包：Wxx
状态：DONE / PARTIAL / BLOCKED
改动文件：...
新增迁移：...
新增/变更 API：...
权限变化：...
测试命令与结果：...
浏览器验证：...
未完成项/风险：...
下一工作包与依赖：...
```

不能只回答“已完成”。测试未跑必须明确写 `NOT RUN`；外部模型不可用必须写原因，不用模拟成功顶替。
