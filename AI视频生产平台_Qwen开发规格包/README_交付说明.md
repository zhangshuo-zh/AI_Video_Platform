# AI 视频生产平台开发规格包

本包依据上传的 `设计稿.md`（设计稿修订记录截至 v0.58，2026-10-31）编写，用于人类评审并交由 Qwen 3.8 Flash 作为开发规格。它把四期功能放进一套统一的产品/系统模型中，但仍保留四期作为交付顺序，避免所有模块重复建设或一次大重写。

## 文件目录

- `00_原始设计稿.md`：原始设计稿副本，便于 Qwen 对照既定决策。
- `01_需求概要说明书.md`：产品定位、模块职责、页面布局/交互、完整业务流程、范围、验收标准。
- `02_系统设计说明书.md`：架构、前后端分层、鉴权、文档/Git、队列/worker、模型适配器、API 契约、成本、审核、部署和测试。
- `03_数据字典.md`：实体关系、字段解释、约束、索引和必须从现有代码核实的 schema。
- `03_数据字典.json`：机器可读的数据字典草案，便于模型检索和生成检查清单；不是可直接执行的 SQL。
- `04_Qwen开发执行指南.md`：执行纪律、开工盘点要求、W00–W18 工作包、依赖、验收与每次改动的汇报格式。
- `AI视频生产平台_开发规范总册.md`：以上开发规范合并后的单文件版本，适合一次性提供给模型上下文。
- `AI视频生产平台_开发规范总册.docx`：供人审阅、批注与打印的 Word 版本。

## 特别说明

1. 当前交付所依据的上传资料只有 `设计稿.md`，没有包含可供独立审计的 `app/` 源码目录。因此，本包保留了“现有代码已实现”与“需要新增/核验”的区别，并要求 Qwen 先读取实际迁移、路由、权限 seed、测试和 CLI 参数，再动代码。
2. 设计稿中的 20 个权限点真实完整名称、各张表的物理列名、当前 API 的全部方法/响应、模型速度与峰值等不能仅凭设计文稿猜测；文档要求从代码或真机实测取得。
3. 本包对设计稿里存在的 worker 进程描述、Shot 归属、Doc 元数据、签字身份等歧义提出了规范决策/待核实项，并未把它们伪装成已由用户确认的既成事实。

## 推荐给 Qwen 的输入顺序

先同时提供 `00_原始设计稿.md`、`01_需求概要说明书.md`、`02_系统设计说明书.md`、`03_数据字典.md`、`03_数据字典.json`、`04_Qwen开发执行指南.md`。首个任务严格按照执行指南中的 W00 做仓库盘点，生成 `CURRENT_*` 与 `SPEC_DIFF.md`，不要第一步就改源码。之后每次只实现一个工作包，跑测试、报告实际结果，再继续下一个。
