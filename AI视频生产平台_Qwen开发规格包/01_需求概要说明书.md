# AI 视频生产平台需求概要说明书

- 文档类型：产品需求与交互规范（PRD）
- 依据：用户提供的《设计稿.md》，版本记录至 v0.58（2026-10-31）
- 面向对象：产品/设计/后端/前端/测试，以及负责编码实现的 Qwen 3.8 Flash
- 目标形态：小团队局域网部署的本地 Web 应用
- 规范用词：**必须**=验收门槛；**应**=默认要求，确有原因才能偏离；**建议**=本规范的设计补充；**待核实**=必须检查现有代码/迁移/测试，不能凭空假定

## 1. 产品定位与设计目标

### 1.1 产品定位

构建一套面向 2–5 人小团队的 AI 视频生产平台，覆盖“项目组织 → 世界观/资产准备 → 小说与剧本创作 → 分镜拆解 → 图像/视频生成 → 配音/配乐 → 自动校验与人工审核 → 素材交付”的全过程。平台本身是**生产流程编排与资料管理系统**，模型通过适配器调用现有 CLI 或国内云端 API 执行；平台不自研推理引擎，也不做在线剪辑软件。

### 1.2 已确认的产品基线

1. 本地 Web，局域网自部署，目标运行设备为 Mac Studio M5 Ultra 96GB；Windows PC 远程参与生成的协议暂不纳入本轮承诺。
2. 前端采用静态 HTML/CSS/原生 ES Module；后端 FastAPI 只提供 `/api` JSON，不在 Python 路由中拼接 HTML。不得自行引入 Node 构建链、React/Next.js 或 Jinja2/HTMX。
3. 数据库采用 SQLite WAL、版本化迁移、Repository 数据访问层；路由层禁止直接写 SQL。
4. 小说、剧本、分镜正文等文件资产保存在文件系统并由 Git 管理；SQLite 保存元数据、状态、关系、生成作业和成本。不得把正文整体迁入数据库。
5. 每个业务对象只有一个模块有写权限；其他模块只读展示、引用或跳转到对象所属模块。
6. 生成中心是唯一生成队列、Job 状态和成本账的写入口；音频中心不能创建第二条队列。
7. 审核中心是校验结果与人工签字的唯一写入口；创作中心和生成中心只读展示审核状态。
8. 默认本地优先；云端模型只使用国内厂商。云端必须由用户在具体镜头/作业上明确勾选，不允许系统因本地慢、失败或质量判定而静默切云。
9. 账号口令登录，无自助注册。超级用户由本机引导/环境变量初始化，明文口令不得写入文档或数据库；会话默认 12 小时，首次登录强制改密。
10. 明确暂不做：ComfyUI 式节点画布、在线时间线剪辑、多租户、SaaS 计费和对外服务。

### 1.3 设计补充的原则

- 先把“数据归属、状态、权限、错误和验收”写清楚，再写 UI；不得先做漂亮的孤立页面。
- 页面主要服务桌面端密集生产工作流。表格优先用于分镜、任务和审核；卡片只用于封面/缩略图/概览，不把每条记录都做成大卡片。
- 任何长任务必须异步执行，前端可离开当前页，回到生成中心仍可查看状态。
- 所有 AI 生成结果都可追溯至输入提示词、模型、参数、引用资产、执行方式和产物文件；不要求第一版做复杂的全链路审计日志。
- 失败必须可理解、可恢复；不得只向用户显示 Python traceback 或空白页面。

## 2. 目标用户与权限语义

### 2.1 角色

| 角色 | 定位 | 典型行为 |
|---|---|---|
| `superadmin`（超级用户） | 系统救援与全局维护账号，不是普通角色权限的组合 | 全部权限；不可经普通用户页面停用、改角色或重置其口令；口令恢复走 `backend/reset_password.py` 或当前已定的安全恢复流程 |
| `admin`（管理员角色） | 维护用户/角色、模型配置、管理项目 | 可访问全局项目与系统设置；受超管账号可见性规则约束 |
| `editor`（制作/编辑） | 日常制作 | 按既有 20 权限点控制，且必须具有项目成员/所有权访问资格 |
| `viewer`（只读） | 查看项目进度、文档/资产/生成和审核状态 | 只能访问权限允许且项目对其可见的数据，不得绕过 API 写入 |

**重要：** 实际系统已有 20 个 `Permission` 权限点和既定角色映射。开发时必须从当前 `bootstrap.py`、权限 seed、迁移及路由声明中读取真实代码，不得根据本文件重新发明或替换已有权限点名称。新增权限若有必要，先提出差异清单与迁移方案。

### 2.2 双层鉴权

所有业务请求必须同时通过：

1. 全局权限点校验，例如是否具备某类读/写能力。
2. 项目可见性/归属校验：管理员或项目所有人/协作人按规则访问；其他人不能通过猜 ID 访问。

规则：看不见的项目返回 404，不能透露项目存在；对看得见但不满足操作级别的请求返回 403。批量端点逐项校验并返回 `done/skipped`，不得因为其中一项失败而放宽权限或把整批不必要地全部回滚。

账号管理必须保留既有安全约束：不能停用自己；不能修改自己的角色；超级用户账号在普通用户管理 API 中只读；用户列表按层级过滤（超级用户层级 2、管理员层级 1、其他层级 0），对高于当前用户层级的目标账号写操作返回 404；删账号前必须转移其项目所有权或明确选择同时删除项目。

## 3. 信息架构与导航

### 3.1 主导航

主导航固定为以下 7 个业务模块和一个工具入口：

1. 项目中心
2. 资产中心
3. 创作中心
4. 生成中心
5. 音频中心
6. 审核中心
7. 设定中心
8. 系统设置（工具模块，不计入七个业务模块）

模块名称使用上述四字名称，不加序号。设定中心与系统设置不得混用概念：设定中心管理作品知识，系统设置管理账号/角色/权限与运行时模型配置。代码文件命名按职责使用 `knowledge.js` 与 `system-config.js`，避免 `setting.js/settings.js` 近似命名。

### 3.2 全站框架布局

- **左侧侧栏：** 桌面默认约 246px；用线性 SVG 图标、模块文字、明确的选中状态。窄屏可缩成图标栏，但不得隐藏关键入口；键盘焦点必须可见。
- **顶栏：** 左侧显示当前项目名称/面包屑与常驻下拉箭头；中间或剩余空间用于当前模块标题/辅助信息；右侧显示主题切换、用户菜单。不要在模块页重复显示一遍“当前项目 X”。
- **内容区域：** 与顶栏内层对齐，最大宽度约 1440px，使用统一的间距、标题层级、表单栅格和空态样式。
- **两套主题：** 白天“极光玻璃”、夜间“暗金片场”，共用同一 DOM 结构；CSS 色彩/圆角/阴影集中到主题 token，不在组件中零散写死颜色。用户手动选过主题后持久化；否则按本机时间 06:00–18:00 使用白天主题。
- **交互一致性：** 下拉箭头与可点击入口常驻可见；状态标签若可筛选必须是实际 `<button>`；复选框统一圆形样式；所有弹窗支持 Escape 关闭（危险确认/正在提交场景另行说明）；按钮有 hover/focus/disabled/loading 状态。
- **可访问性：** 支持 Tab、Shift+Tab、Enter、Space、Escape、箭头键（自绘菜单/列表场景）；`focus-visible` 明显；遵守 `prefers-reduced-motion`；正文不低于设计稿既定下限，弱对比文字不得低于 WCAG AA 的相应要求。
- **状态表现：** 所有异步页面统一有加载态、空态、错误态、成功反馈；表单错误就近显示在控件列，而不是跳到字段名列或仅使用浏览器 alert。

## 4. 模块需求与布局规范

## 4.1 项目中心

### 职责

只维护 `Project`、项目标签、所有人与协作人、项目状态及项目级统计。项目中心不创建/删除集、不编辑文档正文、不维护生成成本明细。

### 布局

1. 页面标题与“新建项目”主按钮。
2. 单行筛选工具条：状态 chip（在产/已归档/全部）、标签 chip、搜索框。
3. 项目表格。列建议为：选择框、项目名称/介绍、内容摘要（N 集 · N 镜 · N 资产 + 已定稿 N/M 集）、所有人、最后打开、最后修改、状态、操作。
4. 项目行点击可切换当前项目；操作按钮为“修改”“成员”“删除”。需避免点击行内按钮冒泡后也切换项目。
5. 多选后显示批量工具条：归档、恢复、追加标签、删除。批量结果在表格上方的持久结果条显示，不用 alert。
6. 新建/修改使用统一弹窗；字段顺序：项目名称、标签、项目介绍、协作人（新建可同时选协作人）；字段名置左、控件置右，控件列最大约 620px。多行字段名贴顶，单行字段名与输入控件垂直居中。
7. 成员弹窗显示所有人（只读）与协作人列表，允许有权限的人添加/移除协作人和转移所有权。无可邀请用户时显示对齐于控件列的说明文字。

### 行为规则

- 默认只显示 `active` 项目；状态筛选为在产/已归档/全部。归档项目从顶栏当前项目选择器中排除，但可在归档/全部列表找回。
- 排序：`last_opened_at` 非空优先，再按时间倒序，再按 ID 倒序；从未打开的项目沉底但不隐藏。
- 打开项目更新 `last_opened_at`，不得更新 `updated_at`。真正内容变更才更新 `updated_at`。
- 创建项目需要名称，介绍可为空但有长度上限（设计稿记录为 500 字），标签去重且最多 10 个、单标签最多 20 字；协作人一次提交。
- 修改项目名称/介绍/标签使用一个整体表单一次 PUT；不要让同一字段在不同入口分头写入。
- 归档是可逆状态，不等于删除。删除是硬删除，必须输入项目名确认；批量删除必须输入固定确认词“批量删除”。
- 批量请求逐项授权：成功项写入，失败项放在 `skipped` 且说明原因；不能将不可见对象从 404 改成 403。
- 搜索词与筛选状态跨局部重绘保存；筛选导致行不可见时，必须同步移除那些行的勾选，保证“被选中的行 = 当前可见且被勾选的行”。
- 当前项目被删除或无有效当前项目时，回退到第一个在产项目；如果只剩归档项目，当前项目置空，不要自动选中归档项目。
- 删除用户前必须明确转移名下项目，或勾选同时删除项目；不可留下悬空 `owner_id`。

### 验收

- 状态、标签、搜索可以叠加且关键词不会因点筛选 chip 丢失。
- 表头全选/半选/单行选择三者始终同步，筛选后隐藏的选择会清除。
- 归档与恢复可逆，顶栏不显示归档项目，项目仍可恢复。
- 删除需输入确认，服务端仍重新校验权限。
- 批量部分成功可显示成功数、跳过数及逐项原因。
- 项目创建和修改后介绍/标签/时间显示与数据库一致。

## 4.2 资产中心

### 职责

资产中心是角色（Character）、场景（Scene）、道具（Prop）资产的唯一写入模块；管理参考/定妆图、视觉描述、一致性提示词、设定条目引用和跨项目复用。

### 布局

1. 顶部标题 +“新建资产”按钮。
2. 筛选条：资产类型、当前项目/全局资产范围、关键词；支持按名称/描述搜索。
3. 主区采用密集表格/紧凑列表，列包含缩略图、名称、类型、归属（当前项目/全局）、更新时间、操作。不要默认把所有资产渲染成大卡片墙。
4. 新建/编辑用统一弹窗或左右主从布局：基本资料字段、视觉描述、一致性提示词、引用设定条目、参考图上传/预览。
5. 参考图点击可看大图；删除按钮清晰但避免误触；无图时显示显式上传按钮。
6. 全局资产可标记“全局”并由有权限的人管理；项目引用不复制资产内容。

### 功能

- 创建、编辑、查询、删除角色/场景/道具。
- 资产名称在同一归属范围与同一类型下必须唯一；冲突返回 409，并在界面显示可理解的提示。
- 上传参考图只接受 PNG/JPEG/WebP，最大 20MB；检查文件实际签名，不仅依赖 Content-Type；HEIC 给出格式转换提示。
- 文件按资产 ID 与随机文件名存于数据目录，前端只使用服务端返回的安全相对路径/资源 URL，不接受用户任意磁盘绝对路径。
- 删除图片时必须校验图片确属该资产；删除资产时只清理数据库明确登记的图片文件与空目录，不删除目录里的未知文件。
- 资产可以引用 `Knowledge`，并可以被多个镜头引用。跨项目复用时保存引用关系，不复制并产生冲突的第二份内容。
- 镜头上只显示资产 chips 与跳转入口，不在分镜页内修改资产内容。

### 验收

- 类型、名称、范围筛选正常；重名准确返回并展示冲突原因。
- 上传格式/大小/签名校验正常；路径穿越和任意路径删除被拒绝。
- 资产更新后，所有引用该资产的镜头可以读到最新资产信息。
- 删除项目/资产时图片清理精准；未知文件不会被一并删除。

## 4.3 创作中心

### 职责

管理 Episode（集）、Doc（小说/剧本/分镜文档元数据与状态）、Shot（镜头表格）、AI 文本创作操作与资产引用。文档正文仍然落在文件系统/Git 中。

### 布局

- **左侧树：** 当前项目 → 集 → 文档（小说/剧本/分镜）；建集、重命名、删除集仅在这里发生。
- **中间主区：** 根据选中节点显示文档编辑器或分镜表格。小说/剧本建议提供正文查看/编辑区域、保存/润色/版本操作；分镜用密集表格而非节点图或卡片画布。
- **右侧上下文区（可折叠）：** 资产引用、知识条目引用、当前文档状态、AI 操作参数/结果。窄屏时转为抽屉，避免三栏挤坏编辑区。
- **分镜表格：** 序号、场景/画面描述、景别、镜头运动、时长、对白/旁白、图像提示词、视频提示词、引用资产、最新生成状态、审核状态、操作。字段必须根据当前数据库已存在列做兼容；新增列通过迁移添加。
- **AI 工具栏：** 起草、扩写、续写、润色、压缩、改写语气、扩展灵感、生成剧情大纲、剧本化、生成分镜建议、生成提示词、从文档抽取角色/场景/道具候选。

### AI 创作与提示词生成的明确行为

- 每个 AI 操作先由用户选择范围（当前段落/当前文档/当前集/选中的镜头）、目标与约束；如果范围不明确，不允许默认把整篇正文提交给模型。
- 灵感扩展至少支持：继续给出情节方向、冲突升级、人物动机、场景变体、结尾悬念。候选以列表展示，用户选择后才并入正式文档。
- 小说/剧本润色需保留用户明确要求不变的角色名、世界观规则、事件顺序、已定稿台词/术语；用户可填写“必须保留/禁止改变”约束。AI 输出先放暂存区，默认不直接覆盖原文。
- 剧本化输出结构化字段：场景标识/内外景与时间、出场人物、动作、对白/旁白、情绪/节奏提示；不满足格式时允许人工编辑，不可将自由散文直接当作结构化剧本成功。
- 分镜建议以一行一个镜头输出，镜头描述可补充景别、机位/运动、建议时长、对白引用、可视化信息和负面约束；用户确认后才写入 Shot。
- **提示词生成器至少支持图像与视频两种目标。** 输入包括镜头描述、引用资产的一致性提示词、设定约束、目标模型档位/能力、画幅/分辨率/时长等适用参数；输出包括主提示词、负面提示词（若模型支持）、必要的分段/镜头运动描述、被引用资产清单、模型适配注意事项。模型不支持的参数不应显示为可提交字段。
- 提示词必须能预览、编辑、复制；经用户确认后才写入分镜字段/生成 Job。提示词生成本身若调用 LLM 也要创建文本 Job，保留输入/输出快照和成本。
- 提示词模板可以按能力、风格、镜头类型、模型档位检索和复用；模板只提供文本与参数默认值，不保存任意 shell 命令。模板的建议数据结构见系统设计与数据字典。
- AI 生成结果需要标明使用模型及生成时间；若模型调用失败，保留输入/错误与可重试入口，但不生成“假完成”文档或镜头。

### 文档与版本规则

- 文档类型固定至少三类：`novel`、`script`、`storyboard`。正文文件路径受平台配置的工作区根路径约束，不允许任意路径读取/写入。
- 状态流建议为 `draft → polishing → finalized`，其中 `polishing` 可由任务驱动；需要退回时必须有明确“退回草稿”操作。不能在没有写入正文的情况下把状态假装为定稿。
- 写入正文成功后才提交 Git；失败时不得留下“状态已更新但正文未写入”的半状态。Git commit 要记录可识别的操作说明和文档路径，不将密钥写入提交内容。
- 同一文件采用占用标记/编辑锁，记录 holder 与时间。掉线锁必须可过期清理；保存时使用版本/更新时间校验，防止静默覆盖他人修改。
- 任何 AI 润色默认生成可预览的修改结果；用户确认应用后才覆盖正式文档（可设置是否允许“一键应用”，但默认不直接覆盖）。采用 diff/版本对比，提交后可从 Git 查看版本。
- 分集状态当前已有 `done` 用于“已定稿 N/M 集”计数。推荐完整显示 `draft/in_progress/done`，但在修改已有枚举前必须检查当前 `PATCH /api/episodes/{id}/status` 校验白名单和已有数据，写迁移/兼容策略。

### 分镜/资产引用

- 镜头引用资产是引用关系，不拷贝角色文本/图片；页面显示资产名、类型、必要时显示参考图缩略图。
- 镜头引用变更只在创作中心通过选择器更新 `Shot.asset_ids` 或现有等价字段；但不得从该页面编辑 Asset 内容。
- 删除仍被引用的资产时，必须明确行为：推荐先拦截并给出引用镜头列表；若项目级联删除场景另走已确认的项目删除流程。不可留下悬空 ID。

### 文本抽取

- 文档抽取人物、场景、道具等候选时必须保留原文偏移/证据片段，不得只把模型归纳结果无依据地直接入库。
- v1 只允许角色/场景/道具候选经人工确认入资产库；镜头候选先导出 Markdown，不直接批量写入 shot。
- 抽取任务走生成中心统一 Job/成本入口；建议具备幂等键，重复提交相同文档版本与抽取参数不应重复落入资产库。

### 验收

- 能在创作中心创建/删除集；项目中心只读显示集计数。
- 小说/剧本文档写入文件，Git 有对应提交；能查看历史与差异。
- 一次润色流程完成：运行脚本/模型、展示差异、用户确认、写回、Git 提交、产生校验报告。
- 分镜每条能保存、引用资产、提交生成作业；资产内容只能在资产中心改。
- 并发编辑被明确阻止或要求合并，不允许静默丢失修改。

## 4.4 生成中心

### 职责

唯一生成队列、生成 Job、模型路由、参数模板、日志/产物、重试/取消与成本账。任何由创作、音频、抽取等功能发起的实际生成，最终都进入本模块的 `job` 队列。

### 布局

1. 顶部为队列概览：等待、运行、成功、失败、需处理数；成本显示按当前项目/时间范围筛选。
2. 筛选栏：任务能力（文本/图像/视频/TTS/音乐/抽取）、状态、执行方式（本地/云端）、模型、项目/集、提交时间。
3. 主表格：状态、任务名/镜头、能力、执行方式、模型/适配器、提交/开始/结束时间、耗时、成本、操作。
4. 选中 Job 展开右侧详情/抽屉：输入摘要、完整参数、提示词、引用资产、日志、错误原因、产物文件、成本计算、重试/取消操作。
5. 成本账页/区块必须位于生成中心；项目中心只读展示累计成本摘要。

### Job 功能

- 从分镜一键提交文本到视频（T2V）、参考图到视频（I2V）、图像生成、配音、音乐、文本润色/抽取等。
- 统一状态建议为 `queued`、`starting`、`running`、`succeeded`、`failed`、`cancel_requested`、`cancelled`、`needs_attention`。现有代码若采用别的状态，需要先映射，不得并存两套状态机。
- 每个 Job 保存能力、执行方式、本地/云端提供方、模型、适配器版本、参数快照、提示词快照、输入引用、输出文件、日志路径、错误代码/摘要、时间字段、重试次数和成本快照。
- 本地生成串行运行，同时最多一个本地生成任务；云端 API 可按限流策略并发提交，但数据库状态写入由平台统一管理。
- worker 必须是与 API 请求处理隔离的独立子进程/执行进程；请求接口只入队并快速返回，不等待模型跑完。队列持久化在 SQLite，服务重启后能够恢复未开始任务，并将“执行中但 worker 已消失”的任务标为可恢复的失败/待重试状态。
- 模型适配器只做薄包装：构造 CLI 参数、启动子进程、收集退出码/日志、定位产物。已有脚本继续可在终端独立执行；不得把推理代码重写进 FastAPI。
- 默认本地优先。对于视频任务，T2V 的本地默认路线为 FastMetal；I2V/大模型档按已确认参数走 mlx-video；图像走 mflux；TTS 走 VoxCPM2；音乐走 ACE-Step。具体可用档必须以机上基准结果和可运行配置为准。
- 云端选项只允许已配置的国内供应商。每一个镜头/作业都需要用户显式选择云端并确认预计单价/成本提醒；系统不得自动从本地失败切换到云端。
- 记录云端请求 ID、供应商响应摘要与计价量，密钥永远不写 Job 参数、日志、错误或 API 响应。
- 失败后用户可在查看错误与参数后重试；重试生成新 Job 记录，关联原 Job，不要覆写原失败的日志/成本。若供应商已产生费用但平台未收到结果，需保留“成本/结果待核对”状态，不可假装零成本。
- 本地成本可以金额为 0，但仍保存耗时/资源指标；云端成本按提交时价格表/用户确认的单价和计量单位记录快照。
- 多币种成本不直接相加；按币种分组展示。如未来要折算统一币种，必须保存汇率与换算时点，作为新需求。
- 加速参数只显示当前适配器/模型真实支持的参数，不能把 5B 专有的开关显示给 1.3B。模型启动失败不得让 UI/API 进程退出。

### 参数模板

- 可保存具名模板（能力、模型/适配器、参数 JSON、适用分辨率/帧数、默认标志、创建/更新时间）。
- 模板是参数预设，不是可执行任意命令；命令二进制与允许参数必须由服务器端 adapter 白名单决定。
- Job 提交时冻结参数快照，之后修改模板不能改变已创建 Job。

### 成本规则

- 唯一口径：`cost_amount = unit_price × quantity`，以 Job 提交时保存的单价、数量、单位、币种为准；金额/成本不能在项目中心手动编辑。
- 失败 Job 的费用应按供应商真实返回/计费情况记录；不能因为 `status=failed` 自动归零。
- 项目成本是 Job 的聚合只读值；未产生金额的本地任务可显示 0 元及其耗时。

### 验收

- 页面提交请求立即返回 Job ID，UI 在作业执行几十分钟时仍可切页/刷新。
- 1 个本地 Worker 串行执行，无两个本地任务同时抢占模型内存。
- 视频 T2V 可调用 FastMetal、I2V 可调用 mlx-video；图像、TTS、音乐适配器可分别端到端运行后再开放对应功能。
- 失败、取消、重试、服务重启恢复状态可测试；日志不会输出密钥。
- 成本记录可与一笔已知云端供应商账单或手工算式核对。

## 4.5 音频中心

### 职责

管理对白与旁白文本关联、声音生成素材、音乐条目及口型 viseme 数据。**它不运行独立队列、不记成本。**

### 布局与功能

- 建议采用三个二级页/标签：对白与配音、音乐素材、口型数据；具体可复用模块原有二级导航模式，但不额外放一个“任务队列”页。
- 对白与配音列表列出集/镜头、说话人、台词、语言/音色、生成音频、字级时间戳、当前状态及“送进生成队列”按钮。
- 配音配置包含声音/说话人标识、语速/音调/可用参数；只展示适配器支持字段。VoxCPM2 的字级时间戳和拼音覆音按实际 CLI 输出映射。
- 音乐条目支持名称、风格/情绪、提示词、时长、参考文件、生成文件、归属项目/集；生成动作交生成中心。
- 口型数据通过 viseme 时间序列挂接到对应音频/镜头；Rhubarb 数据只在需要口型特写的任务保留，不得默认为所有镜头制造无用文件。
- 对白镜头默认本地 VoxCPM2 + Rhubarb；云端音画同生可用，但必须明确接受模型自带音色/音轨与既有定稿对白配音之间的权衡。不能把“模型原生音轨”和“VoxCPM2 最终配音”假设为天然同步。
- 非对白空镜/环境声可实验本地 FastH3 原生音轨；此能力在未完成试听与质量评估之前应标为实验选项，不作为确定交付承诺。
- 音效补声路线（MMAudio / stable-audio-open 等）属于待验证项；在适配器、权重、许可证、成本/耗时没有确认之前不得假装已支持。

### 验收

- 音频中心可查看、组织、引用配音/音乐素材。
- 点击生成只创建生成中心的 Job；本模块不维护单独状态机或队列。
- 生成音频与镜头/对白关联准确，任务进度和成本由生成中心读取。

## 4.6 审核中心

### 职责

自动校验门禁、人工审核队列、审核意见/结果和签字记录的唯一入口。

### 布局

- 顶部筛选：待处理、通过、未通过；目标类型（文档/Job/镜头）；gate 类型（自动校验/人工审核）；集/时间筛选。
- 主区为审核任务表格：对象、当前版本/Job、检查项、状态、提交时间、待处理时长、操作。
- 选择一项后使用主从布局：左/中区查看文档或媒体/日志，右侧显示校验报告、问题列表、审核意见、通过/驳回/退回操作。
- 人工签字需明确显示审核对象、版本/Job ID、签字人、签字时间、结果与意见。必须让签字对象不可歧义，不可对“最新文档”签字却不冻结其版本。

### 功能

- 用统一封装调用现有校验器脚本；输出结构化报告（检查项、结果、严重级别、消息、定位信息、时间）。
- gate 可挂在 Doc 或 Job 上；同一对象可有多个不同 gate 的记录，但一份 Review 记录只能对应一个明确目标和版本。
- 审核者可以通过、驳回或退回修改；驳回/退回必须填写原因。通过后保存签字记录。
- 任意其他模块只显示审核状态和跳转，不提供写 Review 的按钮/接口。
- 对逐句签字场景，必须有可枚举的句子/条目锚点（例如文档路径+Git commit+行/段落标识）；如果目前已有校验器输出格式不足，列为明确 API/数据扩展任务。
- 自动校验通过不等同人工签字通过；两个状态要独立记录。

### 验收

- 审核结果只能通过审核中心 API 创建/更新。
- 审核记录绑定的具体版本或 Job 快照可回溯。
- 通过、驳回、退回都产生持久化记录；非审核角色不可签字。

## 4.7 设定中心

### 职责

世界观、人物关系/历史背景/规则等业务知识条目，以及来源证据快照的唯一写入模块；项目级与全局两种范围。

### 布局与功能

- 左侧可按“全局设定/当前项目”切范围；主区显示条目表格（标题、类别、摘要、范围、最近更新）；详情区编辑正文、标签和证据引用。
- 条目支持创建、编辑、搜索、标签、归档/删除策略（建议优先归档，是否硬删需有引用检查）。
- 证据快照保存文件引用、来源名称/日期、摘录/摘要、必要时的页码或段落定位；来源内容应留在本地资料目录，平台保存可复现的路径和引用元数据。
- 创作中心可读引用设定条目，但只能跳转至设定中心修改。
- 全局条目必须有明确授权策略；项目协作者不能通过引用关系修改全局内容。

### 验收

- 项目设定与全局设定能区分；授权不串项目。
- 创作文档引用条目后可以跳转；条目更新不会改写原始文档正文。

## 4.8 系统设置

### 4.8.1 用户与角色

- 用户表：用户名、显示名、角色、启用状态、最后登录时间；禁止显示密码哈希、会话令牌和初始明文口令。
- 操作：新建用户、启用/停用、重置口令、改角色、删除用户。
- 新建用户填写用户名、显示名、一次性初始口令/重置流程与角色；首次登录强制改密。
- 删除用户必须选择转移所有项目给另一个有效用户，或连同其项目一起删除；有名下项目时不允许静默删除。
- 权限矩阵显示既有 20 权限点 × 3 角色；admin 角色列按既定规则禁用编辑。具体权限点名称来自现有 seed，不能被新文档重新命名。
- 系统设置侧栏入口在 `system:config` 或 `user:read` 任一权限满足时可见；进入子页后仍分别授权，不能因为可查看用户就自动能编辑模型密钥。

### 4.8.2 模型与密钥

- 固定五类能力：文本、图像、视频、TTS、音乐；配置覆盖本地与云端执行方案，共 10 个能力/执行方式配置槽位。
- 配置 provider 标识、模型标识、默认/启用状态、允许参数/能力、环境变量密钥名、健康状态与备注。密钥值只通过 `FV_KEY_<PROVIDER>` 等环境变量读，禁止落库/回传/渲染/写入日志。
- 页面只显示“已配置/未配置”，不得返回密钥的部分明文或完整值。
- 文本 LLM 的云端端点只允许国内厂商（设计稿建议火山方舟或 MiniMax，最终以环境变量及当前可用性为准）。视频云端候选包括设计稿列出的国内服务商，但正式启用前必须复核模型名、API 版本、计价单位、服务协议和许可证。
- 模型默认策略：图像、视频、TTS、音乐默认本地；文本 LLM 需配置受允许的国内云端端点。云端视频必须逐镜头显式选择，不能因为配置了云端就自动使用。
- 对模型能力的真实支持要由 adapter manifest 或服务端白名单驱动；UI 不手写模型参数的假支持。

### 验收

- 密钥从未出现在数据库内容、前端响应、日志、错误提示或 Git。
- 只有具备相应配置权限的人可以修改 provider；普通模块只能读取当前默认模型/状态。
- 新增 provider 不需要复制一套队列或成本逻辑，而是实现统一 adapter contract。

## 5. 共通业务流程

### 5.1 从灵感到视频的主流程

1. 项目中心创建项目，并确定所有人/协作人。
2. 设定中心创建世界观/背景资料；资产中心创建角色/场景/道具与参考图。
3. 创作中心创建集，生成或导入小说，使用 AI 起草/润色；保存前预览差异，确认后写入文件并 Git 提交。
4. 创作中心生成/维护剧本，并将场景拆分为结构化分镜。镜头引用资产和设定条目。
5. 对文档运行校验；审核中心接收自动校验结果，必要时人工审核/签字。
6. 从镜头表选择任务类型、模型档位、参数模板；默认本地。确实需要云端时用户勾选镜头并确认供应商、单价与风险。
7. 生成中心创建 Job、入队、执行、记录日志/产物/成本；前端轮询或刷新读取状态。
8. 音频中心整理对白/旁白/音乐，将生成请求交给同一生成中心队列，获得素材后关联至镜头。
9. 审核中心校验生成结果，标记通过/退回；创作中心/项目中心只读展示进度。
10. 下载/导出素材供外部剪映/达芬奇后期，不在平台中剪辑。

### 5.2 AI 润色/写回流程

1. 锁定目标文档当前版本（文件路径 + Git commit/文件哈希）。
2. 提交文本 Job，保存输入文本版本、提示词、模型和参数快照。
3. 输出到暂存文件/临时结果，不覆盖正文。
4. 用户比较差异并确认应用。
5. 写入目标文件并成功 Git commit；状态更新与 commit 结果需保持一致或提供补偿恢复。
6. 运行校验器，生成 Review/gate 记录。
7. 失败任何一步时保留原文与 Job 日志，提示用户从哪步恢复。

### 5.3 文本抽取流程

1. 选择文档版本与抽取范围。
2. 创建 extraction Job，模型从正文提取角色/场景/道具候选。
3. 每条候选包括类型、建议名称、描述、原文起止偏移、证据文本、抽取 Job/模型、置信度（仅作辅助，不作自动通过依据）。
4. 用户逐条接受、编辑后入 Asset，或忽略；重复候选按幂等键/同类同名规则处理。
5. 镜头候选只导出 Markdown，不自动写入分镜表（v1 范围）。

## 6. 全局交互与状态规范

- **请求状态：** 按钮点击后立即显示 loading/禁用，成功后更新相关区域；避免整页重新渲染导致输入丢失或原生复选框状态闪退。
- **列表局部刷新：** 筛选 chip 点击只更新筛选区与列表，不重建无关输入框；所有筛选状态由模块级 state 统一持有。
- **表单：** 标签在输入控件上方或左栏，统一对齐；验证错误靠近字段；支持取消与 Escape；保存中重复提交要禁用。
- **危险操作：** 删除/清理资产、删除项目、批量删除必须明确对象和影响范围；后端再次校验权限和确认词。
- **空态：** 空态明确说明原因与可执行的下一步；不把用户带到重复写入口。例如创作中心没有集时在本模块创建集，不再引导去项目中心。
- **文件路径：** UI 只处理 API 返回的相对资源 URL，不直接拼任意服务器路径。
- **局部数据一致性：** 更新一个对象后，当前页面相关的派生计数和跨模块只读状态要刷新；避免把“最后打开”错误计为“最后修改”。
- **可观测性：** 对长任务展示可理解状态，不假装所有模型都能提供百分比进度；若底层脚本没有百分比，则显示“运行中/已运行时长/阶段日志”。

## 7. 非功能需求

### 7.1 性能与容量

- 目标规模为 2–5 名局域网用户、万级任务记录；SQLite WAL 为默认方案，暂不预设 PostgreSQL。
- 长视频生成期间浏览器操作、API 查询与用户管理不应被阻塞。
- 本地生成同一时刻最多一个任务；默认逐任务加载/释放模型，常驻模型开关默认关闭。
- 项目列表聚合统计尽量通过一次查询/聚合返回，不为每一行发起额外网络请求。

### 7.2 安全

- 所有业务端点明确声明权限；不依赖前端隐藏按钮实现授权。
- cookie 会话 HttpOnly、SameSite=Lax；生产配置下仅允许白名单 CORS，默认关闭跨域。
- 所有模型密钥从环境变量读取并遮蔽；命令行、异常与日志对密钥/授权头脱敏。
- 上传文件校验扩展名、文件签名、大小；防路径穿越和任意文件删除。
- 文件访问限定在配置的工作区/数据目录内，禁止 `..`、符号链接绕过与任意绝对路径。
- 删除项目、用户、资产要在事务和文件清理策略中定义失败补偿；优先先收集清单，数据库提交后再删除文件或采用可恢复的删除清单，避免数据库已删而实际文件清理失败却无记录。
- 不把账号口令、API Key、完整环境变量或个人文件路径写进需求文档/提交记录。

### 7.3 可维护性

- SQLite 结构只能通过版本化迁移更改；每个迁移事务独立，启动时执行迁移前自动备份现有数据库，保留最近 5 份（已有逻辑需核实）。
- 所有 SQL 位于 Repository 层；业务逻辑位于 services/access 层；Router 做校验、调用服务并返回响应，不跨 Router 相互导入。
- CLI 适配器可独立从终端复现；平台不修改第三方脚本的核心行为。
- 业务功能只保留一个写入入口；共同组件（弹窗、表格、表单提示、状态标签、请求错误处理）统一。

### 7.4 兼容和迁移

- 新增字段需有向前迁移与旧数据回填策略；已有 API 路径/状态在非必要时保持兼容。
- 如果发现设计文档与当前源码有差异，先记录为 `SPEC-DIFF`：现状、依据、目标、迁移、回归测试；不可整体重写覆盖已有实现。

## 8. 四期功能融合后的范围与优先级

本节描述**完整产品目标**。即使实现按四期交付，功能边界也要按完整产品来设计，避免四期互相拆出重复入口。

### P0：平台和对象基础（一期基础）

- 登录/登出/当前用户/修改密码/强制改密；账号、角色和权限管理；项目所有权和项目成员检查。
- 项目创建、编辑、列表/筛选/归档/批量操作/硬删除确认/所有权转移。
- 集、资产、参考图、基础文档文件管理、Git 提交、编辑占用标记。
- 系统设置的本地/云端双轨 Provider 配置页（密钥值不入库）。
- 通用布局、主题、请求错误处理、迁移/Repository/备份。

### P1：生成闭环（二期核心）

- Job/Task 状态与 SQLite 持久队列；独立 worker；日志、失败恢复、取消/重试。
- Model adapter contract；FastMetal T2V、mlx-video I2V、mflux 图像、文本 LLM（国内 API）接入；云端视频 provider 按显式选择启用。
- 参数模板、输入/参数快照、产物登记、成本记账、项目只读成本汇总。
- 机上模型基准测试，把耗时、峰值内存、质量、分辨率、帧数填回档位配置；未经实测不得伪造性能数据。

### P1：创作与审核闭环（三期核心）

- 完整 Doc 状态机、AI 起草/扩写/润色/剧本化、分镜表格、资产引用选择器。
- 文档 Git 版本/差异、占用与冲突保护。
- 文本抽取候选与证据偏移、候选审核入资产。
- 自动校验器 gate、Review 状态、人工签字、逐句签字需要的锚点。

### P2：音频与项目看板（四期核心）

- VoxCPM2 TTS、音频文件和字级时间戳；Rhubarb/viseme 与镜头挂接。
- ACE-Step 音乐生成与音乐条目管理。
- 环境音/音画同生的实验性接入必须经过单独基准和许可核查，不默认纳入 P0。
- 项目进度看板：集完成数、镜头生成状态、审核通过数、失败/待处理任务、成本摘要。
- 导出项目资产清单/镜头素材清单供外部剪辑软件使用（不实现在线剪辑时间线）。

## 9. 重要设计冲突与规范决策

| 编号 | 冲突/风险 | 本说明书的规范处理 | 实施注意 |
|---|---|---|---|
| D-01 | 设计稿一处提“同进程后台 worker”，多处要求生成 worker 独立进程 | 统一采用独立 worker 子进程；API 进程只负责入队/查询/状态编排 | 不在请求线程里生成；SQLite 队列是唯一状态源 |
| D-02 | Shot 被描述为属于 Doc（剧本），现有 API 却按 `/episodes/{id}/shots` 访问 | 先保持既有 API 与迁移的 `episode_id` 关系兼容；检查现有 schema 后，再用可选 `doc_id`/关联表表达文档关联，不破坏现有端点 | Qwen 必须先读现有 `0004_content.sql` 与 models/repositories，确认后写 `SPEC-DIFF` |
| D-03 | Doc 是九实体之一，但正文应留文件，当前初期迁移是否有完整 `doc` 表需核查 | 文件保存正文；数据库保存路径、类型、所属集、状态、Git 引用等元数据 | 若当前缺表，用增量迁移建立，不能搬正文进 DB |
| D-04 | 当前分集状态显示 `done`，但完整状态值没有在正文列明 | `done` 为必须支持值；其他状态从现有 `Literal`/模型读取。建议阶段性状态 draft/in_progress/done，但需先核对兼容 | 不直接改写已有状态枚举，新增值要有迁移/回填/测试 |
| D-05 | “五类能力 × 本地/云端”与“每种能力恰好一个默认”可能被解读为多个默认 | 每个能力应只有一个有效默认路线；日常图像/视频/TTS/音乐默认本地，文本 LLM 用允许的国内云端端点；云端视频仍需逐 Job 人工确认 | 配置页必须展示有效默认与可用性，不能静默 fallback |
| D-06 | 逐句人工签字需要识别签字人，但身份基线又倾向业务数据不引用账号 | Review 需要明确 signer 身份，建议对 Review 设唯一 `reviewer_user_id` 例外；其他业务实体不加普遍性的 created_by 审计字段 | 实施前核对现有 schema，确认是否接受此例外；不可用自由文本冒充可信身份 |
| D-07 | 资产图片路径的持久化方式未从设计稿完全确认 | 先检查当前 `asset` schema 和 `/api/assets/{id}/images` 实现；数据字典提供逻辑定义，实施时优先沿用现有字段/存储方式 | 不能引入第二套图片登记机制导致一份文件多份真相 |
| D-08 | 模型价格与单价随供应商更新，文档中有旧报价 | 所有价格视为待复核数据，运行时按提供方最新计价/用户确认值记录快照 | 不硬编码旧价格，不虚构成本与耗时 |

## 10. 不在当前范围内

- ComfyUI 式节点图工作流编辑器。
- 在线视频时间线剪辑、转场、字幕时间轴合成与最终成片渲染器。
- SaaS 多租户、自助注册、对外开放用户/计费平台。
- 将小说/剧本全文搬入 SQLite。
- 静默自动切换云端、自动将未审文本标记为定稿、自动将抽取候选直接入资产库。
- 不经真实机上测试即宣称模型的耗时/峰值/画质/帧率。
- 未确认许可、国内可用性、API 版本或计价方式的供应商，不能作为默认生产路径。

## 11. 完整验收总场景

上线前至少通过以下端到端场景：

1. 未登录访问业务 API 得到 401；健康检查不依赖登录。登录后首次改密；登出后会话立即不可用。
2. viewer 不能写项目/资产/文档/模型配置；editor 即使具有某全局权限也不能访问自己不是成员的项目；不可见项目返回 404。
3. 创建项目并邀请协作者；协作者可执行被授权的制作操作，但不能删除项目或管理成员；归档项目不会成为当前项目回退目标。
4. 创建资产、上传有效/无效格式图片、引用资产到镜头、删除图片/资产；验证拒绝越权路径和保留未知文件。
5. 小说/剧本保存成文件、Git 有提交；并发编辑能提示冲突；润色可以预览、确认写入、生成校验报告。
6. 生成中心创建一个本地视频 Job，API 快速返回；worker 串行调用指定 CLI，产物和日志落盘；失败可重试且保留原始失败记录。
7. 用户显式勾选云端镜头后，页面显示供应商/计价单位/预计成本；未经勾选，即使本地失败也不产生云端请求。
8. 成本按 Job 明细汇总，项目中心仅显示只读总览，多币种不混加。
9. 音频中心提交 TTS/音乐任务后，只在生成中心出现一个 Job；不存在第二条队列。
10. 审核中心创建自动 gate 和人工 Review；只有审核中心可签字；签字绑定具体文档 Git 版本/Job ID。
11. 迁移旧数据库后 `PRAGMA foreign_key_check` 无异常；备份可恢复；所有新功能回归现有的项目、用户、标签、归档、协作人和主题交互。
