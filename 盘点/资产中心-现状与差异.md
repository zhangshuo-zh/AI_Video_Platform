## 2. 存在但不完整或有缺陷的

1. **没有"编辑"这条路**。43 条路由里资产只有 create / delete / 图片两个，**没有 `GET /api/assets/{id}`、没有 `PUT/PATCH`**。指令 §4.1、§4.3 要的名称／简介／标签／描述／一致性提示词编辑，**后端根本没有写入口**，前端也就没有详情。这是本轮最大的一块。
2. **删除没有引用保护**。`delete_asset` 不查 `shot.asset_ids`，删完镜头留悬空 ID——前端那句确认文案「已引用的镜头不会被改」是**诚实的**，但指令 §4.5 明确不允许静默悬空。
3. **关联分镜查不出来**。`shot.asset_ids` 是 JSON 文本列（`0004_content.sql`），没有关联表。好消息：SQLite 3.54 的 `json_each` 可用（本机实测），反向查询不必建表也能做。
4. **侧栏分类与页内分类名称错位**（真 bug）：`modules.js:20` 的 subs 是 `全部／角色／物品／场景`，`assets.js:10-15` 的 `KINDS` 是 `全部／角色／场景／物品` —— index 2/3 互换，点"物品"看到的是"场景"。
5. **筛选是整页重渲染**：`assets.js:101-106` 点 chip 走 `app:refresh`，与项目中心 v0.57 修掉的是同一个毛病；且 chip 是 `<span>` 挂手型光标，键盘不可达。
6. **错误伪装成空态**：`assets.js:31` `catch { list = [] }` → 403/500 时显示"还没有资产"。
7. **页头文案写着"跨项目复用"，但库里做不到**（见 §3.1）——这句是假标语，属指令 §3.1 禁止的"虚构数据填充正式页面"的文案版。
8. **没有封面概念**：`ref_images` 是数组，前端按顺序画，第一张事实上是封面但没有语义，也没有"设为封面"的操作。
9. **两处原生 `confirm()`**（`assets.js:152/161`），与项目中心的自绘危险弹窗是两套标准。
10. **登记表单是页内常驻一行**（`assets.js:84-95`），指令 §3.2 要的是弹窗＋先选类型再出字段；且现在**填不了** summary／标签（只有 kind/name/prompt 三个框）。

### §5.2 的真实依赖链（必须先说清，不能拿模拟数据冒充）

`接口草案-抽取.md` 定义的数据流是 `POST /api/extract/runs → 写 job(queued) + extraction_run → worker 取 job → 读正文 → 调 LLM → 落 extraction_item`。逐环核对现状：

| 环节 | 现状 | 阻塞点 |
|---|---|---|
| `job` 表＋持久队列＋独立 worker | **不存在**（W07 未做） | 抽取按草案必须走 job，否则"成本单一源"第一天就破 |
| 正文文件与 `source_path` | **不存在**（无 `doc` 表、无 workspace、无 Git，W05 未做） | 草案 §3.1 的 `source_path` 无处可取 |
| 文本 LLM provider | 十个槽位全空，且本机只有 `DEEPSEEK_API_KEY` 与后端约定的 `FV_KEY_*` **命名不匹配** | W06/W10 |
| 候选表与确认接口 | 不存在 | 可与 W07 一起建 |

**所以本轮不该实现抽取**。按指令 §十第五步自己的话："若该流程依赖其他尚未完成模块，先明确依赖，不要使用模拟数据冒充真实完成。" 我能做的只有一件有实际价值的事：**把 `asset` 表补上草案 §2.4 要求的 `aliases` 列**（草案的 asset 定义比现有表多这一列，抽取 accept/merge 全靠它做去重合并），这样将来接抽取时不用再动资产表。

## 4. 可能破坏现有数据的操作与防护

| 风险 | 防护 |
|---|---|
| 改 `asset.project_id` 为可空（全局池） | SQLite 不能 `ALTER COLUMN`，**必须重建表** ⇒ 迁移前先备份（`migrate.py` 已有）、迁移后跑 `PRAGMA foreign_key_check`、`uq_asset_name` 要重新定义（NULL 参与唯一性的语义在 SQLite 里是"NULL 互不相等"，会让全局资产重名拦不住） |

## 5. 最小变更方案（指令 §十 第二步，待一个裁决后开工）

**不动的部分**：`shot.asset_ids` 的关联模型、图片接口与其校验、权限点名称（复用 `asset:read/write`，不新造）、两套主题与令牌、其他模块。

**要做的**（按依赖顺序）：

1. **迁移 0012**：`asset` 加 `aliases TEXT NOT NULL DEFAULT '[]'`（为将来的抽取合并铺路，纯增量）。
2. **后端补写入口**：`GET /api/assets/{id}`、`PUT /api/assets/{id}`（名称／类型／简介／标签／描述／一致性提示词／aliases 一次整体提交，重名 409、改类型也要查重）、`GET /api/assets/{id}/shots`（`json_each` 反查引用镜头，返回项目／集／镜号）。
3. **删除引用保护**：`delete_asset` 先查引用，被引用则 **409 带清单**；前端把清单显示出来并给"去创作中心处理"的跳转。
4. **封面**：`PUT /api/assets/{id}/cover`（把某路径移到 `ref_images` 首位），不加列。
5. **标签**：新表 `asset_tag`（与 `project_tag` 同构），`AssetIn/Out` 带 `tags`。
6. **前端两层结构**：`assets.js` 改成卡片网格＋统计条＋搜索/筛选/排序（纯前端，状态存模块级，切分类不清空搜索词）；新增 `asset-detail.js` 详情页（基本信息／参考图画廊／提示词／关联分镜只读／删除）。
7. **路由加一个深链槽位**：`#assets/<sub>` 保持不变，新增 `#assets/<sub>/a<id>` 指向详情（`router.js`＋`navstate.js`＋`app.js` 各几行，带回归用例证明老地址仍有效）。
8. **顺手修掉 §2 里的四个老毛病**：subs 名称错位、chip 改真 `<button>`、`catch{[]}` 改成"读不到＋重试"、两处 `confirm()` 换自绘弹窗。
9. **测试**：Repository 层（重名查重／aliases 读写／封面移到首位）、API 层（编辑 409／越权 404／删除引用保护 409／cover 非法路径 404）、前端静态断言（无 fetch、无 alert 外溢）、真浏览器端到端（建→编→传图→设封面→删被引用→跳详情→刷新仍在）。

**待你裁一条**：全局资产池（指令 §5.3）本轮做还是下一轮。我的建议是**下一轮**——它要求重建 `asset` 表（`project_id` 改可空）、重定义唯一索引、新增"项目引用全局资产"的关系表，而"谁能建／谁能改全局资产"这条授权策略规格自己也没定（W00 冲突清单里的 C4）。本轮先把页头那句"跨项目复用"的假标语改成实话，其余八条不受它影响。你要是想一次做完，我就把 C4 按"仅管理员可建全局资产、项目侧只引用不复制"来落，一并做进去。

## 6. 实施回填（2026-11-01，v0.60）

用户裁"一起做，冲突以本次指令为准" ⇒ C4 按 §5.3 落成：**全局资产人人可读，写与删只放管理员；引用不复制；全局不可收回成项目资产**。上面 §5 的九条全部落地，另有两处与盘点时的预判不同：

1. **没有建 `asset_project_ref` 中间表**（§5 第 6 条原本预备要建）。想清楚之后不需要：镜头的 `asset_ids` 本来就存任意资产 id，"全局资产被跨项目引用"这件事已经表达得完整；再加一张表只会成为第二个真相源，还得同步。
2. **唯一索引必须拆成两条部分索引**（§4 只写了"要重定义"）。SQLite 认为 NULL 彼此不相等，原来那条 `(project_id,kind,name)` 对全局行等于不设防 ⇒ 拆成 `WHERE project_id IS NOT NULL` 与 `WHERE project_id IS NULL` 两条，并写 `test_两条全局资产同名要拦住` 钉住。

**测试**：`pytest tests -q` → **116 passed**（其中 `test_assets.py` 14 项）；CDP 真浏览器端到端 **22 项全过**，日／夜两套主题截图各看过。

**被真渲染抓出来的两个自己的错**（都补了断言）：`AssetOut` 漏带 `created_at／updated_at` ⇒ 详情页摆出"创建于 undefined"；详情页上传框的选择器抄了列表页的 `[data-upload]`（它其实是 `#ad-upload`）⇒ 事件根本没绑上、上传静默失效。第二条尤其说明**"上传"这件事只有真点一次才算验过**。

**仍未做**：抽取候选（§5.2）——`job`／`doc`／LLM provider 四环全断，本轮只补了 `aliases` 那一块砖；关联设定条目（§4.1）被设定中心整体阻塞。
