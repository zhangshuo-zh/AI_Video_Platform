## 4. 状态与反馈（规格 01-3.2-7 / 01-6 的落点）

- **没有统一 loading/toast 组件**。全站唯一"就地说不弹 alert"的正面例子是项目中心的批量结果条 `.batch-msg`（`projects.js:328-332`）。
- 进行中状态靠**按钮 disabled** 表达（15 处），无 `aria-busy`。
- 空态统一 `.empty` + `.empty-t`（`app.css:317-320`），但**占位页把空态当内容用**。
- 错误态四条互不相通的路：`alert()`（**全站只有 `util.js:20` 一处**）、闸门内联、页面级"读不到 X"、局部 `.t-bad` 红字。
- **最坏的一条**：`assets.js:31`、`writing.js:47/50/80` 用 `catch { x = [] }` 把 403/500 **伪装成"还没有数据"**，无重试入口。规格 01-1.3-5「失败可理解可恢复」直接不满足。
- **假成功**：`api.js:118/129/137` 三个 DELETE 忘挂 `toJson` → 后端拒绝也照样刷新并当作删除成功（详见 `CURRENT_API.md` §4-1）。
- **原生 `confirm()` 五处**（`assets.js:152/161`、`writing.js:196/241`、`system-users.js:257`）与项目中心的自绘危险弹窗**并存两套删除确认标准**。
- **401 只在 boot 处理一次**（`app.js:478`）：会话 12 小时过期后运行中任何写操作只弹 alert，没有重登出口。

## 6. 窄屏（规格 01-3.2-1「不得隐藏关键入口」）

断点 4 个（`app.css:839/842/847/868`）。**两条与规格直接冲突**：

1. `app.css:854` `.nav-sub{display:none !important}` —— 860px 以下**二级导航彻底消失**，正是"不得隐藏关键入口"禁的那种做法。
2. 表格**没有横向滚动容器**：`overflow-x` 全仓零命中，`<table>` 直接坐在 `.card` 里，而 `app.css:463` `.card:has(table){overflow:hidden}` 会把溢出**裁掉**。项目中心 7 列（含两个 `slice(0,16)` 的时间列）与用户与角色的权限矩阵（每列写死 `width:132px`，`app.css:553`）在窄屏必然被裁且**用户无法拖看全**。

另外 `.modal-box{width:452px}`（`app.css:701`）、`.pal-box{width:420px}` 都没有 `max-width:100%`，视口 <492px 会撑出遮罩内边距。

## 7. 外观纪律（规格 01-3.2-4）

令牌两块：`:root`（`app.css:10-108`，白天极光玻璃）与 `[data-theme=night]`（`:112-189`，夜间暗金片场）；前置脚本 `index.html:11-19` 在样式表生效前定主题；两枚切换钮（顶栏＋闸门）；`prefers-reduced-motion` 全局管辖（`:868-872`）。基准正文 13px，提示档 11.5px（18 处），最小 10px 只有 `.kbd` 与 `.img-del` 两处。

**违反"除变量外不硬写颜色"这条纪律的**：`app.css:672`、`:680`、`:423`、`:273` 四处 `rgba(0,0,0,.x)`／`rgba(255,255,255,.3)` 阴影写在组件规则里（黑白阴影两套主题共用同一值，夜间不会变浅）。另外 `'fv.theme'` 这个键名在 `index.html:14` 与 `app.js:402` 各写一遍，两处注释已互相点名"改一处要改两处"。
