# W11 文档 AI 操作：取数、提示词、真调用与边界

日期：2026-11-01　设计稿：v0.71　代码：`backend/docai.py`、`backend/services.py`、`frontend/js/views/writing.js`

## 1. 这一包解决什么

小说／剧本页在 W05 已经能写、能存、能看 Git 历史，但没有“让模型帮我改一段”的入口。W11 把六种改写接上，并立三条硬规矩：

1. **一次改写就是一条 Job**：实际模型调用不发生在请求线程里，提示词与基线版本冻在作业行上。
2. **先看 diff 再写回**：作业成功不等于正文变了；只有人点「应用并提交」才落盘。
3. **写回只有一条路**：复用 `services.save_content()`，锁、冲突、原子写与 Git 提交不重写第二套。

## 2. 六种操作与落点

| 操作 | 默认范围 | `apply_mode` | 说明 |
|---|---|---|---|
| 起草 draft | 整篇 | `replace_document` | 按标题与要求起新正文；旧正文只作参考 |
| 扩写 expand | 选中（无选中则整篇） | `replace_selection` / `replace_document` | 保留原意与顺序，补动作、感官与细节 |
| 续写 continue | 整篇 | `append` | 紧接最后一句往后写，应用时追加到文末 |
| 润色 polish | 选中（无选中则整篇） | `replace_selection` / `replace_document` | 只改表达、节奏与用词，不增删情节 |
| 剧本化 scriptify | 选中（无选中则整篇） | `replace_selection` / `replace_document` | 场景标题＋动作＋对白 |
| 提示词 prompt | 选中（无选中则整篇） | `replace_selection` / `replace_document` | 每镜一行，只写画面看得见的东西 |

起草与续写在前端也不给“选中段落”这个选项：后端会把范围强制成整篇，界面上再留着等于骗人。

## 3. 范围与选区

- 前端传 `start/end` 与 `selection_text`；服务端拿**盘上正文**重新切片。
- 偏移对得上就按偏移；对不上时，如果这段文字在正文里**只出现一次**，按文字找回位置。出现多次、找不到、空白、超 30,000 字都回 422——宁可让人多选几个字，也不猜要改哪一段。
- 为什么要文字兜底：浏览器偏移按 UTF-16 算，emoji 会让它与 Python 码点差一截。
- 整篇操作的上限也是 30,000 字；这不是模型上下文上限，是“这一次可能花多少钱”的上限。

## 4. 提示词（逐字）

公共尾句（六种都带）：

```
只输出结果本身，不要解释，不要用 Markdown 代码块包裹，不要在开头写“好的”“以下是”。
```

有附加要求时，先加一行：

```
额外要求（必须遵守，但不许改变下面给出的原文事实）：<用户输入，最多 2000 字>
```

六种操作的主体：

```
起草   你是一位中文小说/剧本写作助手。请为《标题》起草一段正文。
       已有正文（只作参考，可为空）：<全文或“（还没有正文）”>
       要求：写出可以直接放进作品里的正文，人物、场景、语气要统一。

续写   请续写《标题》下面的正文，紧接最后一句，保持人称、语气与世界观。
       已有正文：<全文>
       只输出续写出来的那部分，不要重复已有内容，不要总结。

扩写   请扩写《标题》下面这段文字，保留原意、事实、人物与时间顺序，
       可以补充动作、感官和细节，但不要新增情节转折。
       待扩写的段落：<选中>
       只输出扩写后的段落。

润色   请润色《标题》下面这段文字，保持原意、事实与人物口吻，
       只改表达、节奏和用词，不增删情节。
       待润色的段落：<选中>
       只输出润色后的段落。

剧本化 请把《标题》下面这段小说改写成剧本格式：先给场景标题（地点/时间），
       再写动作与对白；对白前写人物名，动作用现在时。
       小说原文：<选中>
       只输出剧本正文。

提示词 请从《标题》下面这段正文提炼可用于文生视频的镜头提示词。
       每镜一行，格式：镜号｜画面主体与动作｜镜头运动/景别｜光线与氛围。
       只写画面能看见的东西，不要写心理活动，不要解释。
       正文：<选中>
```

参数固定为 `max_tokens`（起草/扩写/续写/润色 4096、剧本化 8192、提示词 2048）、`temperature=0.7`、`thinking=false`。三者都在 DeepSeek 清单的白名单里；`thinking` 关掉是因为要的是正文，不是思考过程。

## 5. 作业里冻结了什么

`job` 行：

- `capability=text`、`kind=text`、`execution_mode=cloud`、`provider=deepseek`、`model=deepseek-flash`
- `prompt_snapshot`：上面拼好的完整提示词（含选中的原文）
- `params`：`max_tokens/temperature/thinking`
- `input_refs`：`doc_id`、`doc_title`、`operation`、`operation_label`、`base_version`（正文 sha256）、`scope`、`selection_start/end`、`apply_mode`
- 成本列与 `pricing_snapshot`：清单单价×用户确认的数量，`billable_status=pending_reconciliation`

**`kind` 为什么仍是 `text`**：`job.kind` 有 CHECK 白名单，为一包功能重建整张表不划算；“这条 text 作业属于哪份文档”由 `input_refs` 回答，预览与应用都按它校验，跨文档一律 404。

## 6. 计价

- 单价来自 adapter 清单：`deepseek-flash` 输出忙时 8 元/百万 token（2026-11-01 官方口径），单位 `million_token`。
- 预计数量 = `ceil((输入字数 + max_tokens) / 1000) / 1000`，最小 0.001。
- 本次真验收：选中 31 字，`31 + 4096 = 4127 → 0.005` 百万 token，`0.005 × 8,000,000 micros = 40,000 micros = ¥0.04`。
- 实际用量只有 150 token（131 输入 + 19 输出），远低于预计——这是**预计上限**，不是结算值；账单仍是 `pending_reconciliation`。
- 提交必须带完整 `estimate` 与 `user_confirmed_cloud=true`；单位、币种、单价任一项与清单不符回 422。
- **健康不过不建作业**：缺密钥那种失败一次请求都发不出去，不该在账上留一行。

## 9. 失败时原文不动（pytest 证据）

`tests/test_doc_ai.py` 里三条：

- **模型 429**：作业 `failed`、`error_code=provider_rate_limit`、错误消息里没有密钥；预览 `can_apply=false`、`diff=""`；再点应用 422；盘上版本与内容都不变。
- **运行期间被改过**：AI 跑完后另一个编辑者先保存了一版；预览 `conflict=true`、`can_apply=false`、`diff=""`；应用回 409；盘上仍是对方那份。
- **锁在别人手里**：`docs.acquire_lock(doc, admin, 15)` 之后应用回 423；正文不变。

另外：作业没跑完就应用回 422；拿别的文档 id 查这条作业回 404；不存在的作业回 404。

## 10. 边界

- 只做文档级改写，不碰分镜表：剧本化产出文本，不会自动拆 `shot` 行。
- 没有多轮对话，一次操作一条独立作业。
- 不做三方合并：版本冲突只拒绝。
- 应用后不重算账单：实际用量只进 `resources_json.provider`，成本仍是提交时那张确认单。
- 模型固定走文本默认轨（本机 `deepseek/deepseek-flash`），没有“这份文档临时换模型”的入口。
- 平台只保证位置、版本与历史，不保证文风与事实；润色质量靠提示词约束。
