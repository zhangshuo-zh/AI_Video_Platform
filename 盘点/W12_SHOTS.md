# W12 分镜表：整体编辑、只读引用、每镜作业

日期：2026-11-01　设计稿：v0.72　代码：`backend/routers/content.py`、`backend/repositories/content.py`、`frontend/js/views/writing.js`

## 1. 这一包解决什么

分镜在 W09 只做到“一镜一行，点生成把提示词交给生成中心”，字段不能回头改，资产引用也没有入口。W12 把它补成一张能对着改的表：

1. **四字段整体编辑**：内容、提示词、时长、引用资产一次提交，不一个字一个字地存。
2. **引用只读**：表格里是 chip，点它去资产中心；资产内容不在这一页改。
3. **作业只读**：每镜挂几条、最新什么状态看得见，取消／重试仍在生成中心。
4. **快照不动**：改镜头只写 `shot` 行，已提交作业的提示词与参数一个字都不变。

不做节点画布。

## 2. 关系定案：Shot 属 Episode

初稿 §2 写的是“Shot 属 Doc（剧本）”，但 0004 迁移建的是 `shot.episode_id NOT NULL`，接口也一直是 `GET /api/episodes/{id}/shots`。**以代码与数据为准：属 Episode**；这次把设计稿那张表一起改正。

**旧 API 向后兼容**：没有删路径、没有改字段、没有把 `episode_id` 换成 `doc_id`。只新增两个入口：

- `PUT /api/shots/{shot_id}`：整体更新四字段。
- `GET /api/jobs?episode_id=&shot_id=`：给作业列表加两个筛选参数（原参数一个不动）。

## 3. 字段映射（以当前 schema 为准）

| 界面列 | `shot` 列 | 说明 |
|---|---|---|
| 镜号 | `seq` | 创建时按集内顺序排，**不可编辑**；要换位置就删了重建 |
| 内容 | `summary` | 必填，≤500 字；动作、对白都写在这里 |
| 提示词 | `prompt` | 可空，≤2000 字；空时生成用 `summary` |
| 时长 | `duration` | 秒，`0 < x ≤ 60` |
| 引用资产 | `asset_ids` | JSON 数组；去重保序，最多 40 条 |
| 作业 | `job.shot_id` 反查 | 不建冗余列，一镜几条以作业表为准 |

题面说“完整表格字段以当前 schema 映射为准”，所以 **01-4.3-L4 的六列（景别／运镜／对白／图像提示词／视频提示词／审核状态）没有新增**。现在 `summary` 承担动作与对白，`prompt` 承担生成提示词；真要拆列，得先定这些字段如何进入生成 argv，否则就是第二套事实来源。

## 4. 服务端校验

`_checked_asset_ids(project_id, raw)` 一次做四件事：

1. 必须是整数（布尔不算）；
2. 去重保序；
3. 最多 40 条；
4. `AssetRepository.usable_ids()` 只认 `project_id = 本项目` 或 `project_id IS NULL`（全局资产池）。

任何一条不过回 422，消息里指出是哪一条。**前端 picker 只是把可选的摆出来，最终能不能存由服务端复核**——直接调接口塞一个别的项目的资产同样被拒。

其他：内容为空、时长越界由 `ShotIn` 的 Pydantic 约束回 422；更新会 `touch` 项目的最后修改时间（与 W01 的九条写路径同一条规矩）；跨项目看不见 404、看得见但只有读权限 403。

## 5. 作业：一镜多条，筛选下推

`job.shot_id` 是普通外键，不设唯一，所以同一镜连提两条（重跑、换档位）各自成行。这一包之前作业列表没有按镜筛的能力，前端只能拉全项目再自己过滤。

新增 `episode_id` 与 `shot_id` 两个查询参数，执行顺序是：

1. 给了哪个实体就先 `ensure_by` 绕回项目——顺带把“看不见的实体”挡成 404；
2. 若同时给了 `project_id` 且与实体不属于同一个项目，回 404，不泄露它属于谁；
3. 再用 `_visible_ids()` 做项目可见范围，最后把条件传进 `JobRepository.list()`。

前端**一集一次取 200 条**（`?episode_id=<当前集>&limit=200`），按 `shot_id` 分组后每行只画“几条＋最新状态”。不给 20 镜的集发 20 个请求，这一列也不需要全量。

## 6. 快照为什么不会变

`ShotRepository.update()` 只做一件事：

```sql
UPDATE shot SET summary = ?, prompt = ?, duration = ?, asset_ids = ?
 WHERE id = ?
```

然后 `touch(conn, "shot", shot_id)`，从不写 `job`。作业的 `prompt_snapshot`、`params_json`、`shot_id`、`queued_at` 都是提交那一刻冻进去的，执行时读的也是这些列，所以改镜头影响不到已提交的作业。

测试 `test_改镜头不会改已提交作业的输入快照` 逐项比对四项；真浏览器又比对了一遍改镜前后的作业详情。

## 7. 界面

- 表头六列：镜号／内容·提示词／引用资产／时长／作业／操作。内容主行，提示词压成一行灰字（`title` 里给全文）。
- **新建与编辑共用一张弹窗**（`#shot-modal`）：标题在“新建镜头／编辑第 N 镜”之间切换。字段名在左、控件在右，与全站表单同一条规矩。
- 资产 picker：搜索框＋按角色／场景／道具分组的候选＋上方常驻的“已选 N”。点候选选中（蓝），点已选 chip 撤掉；搜索匹配名字、类型、简介、别名、标签。
- 表格里的资产是 `.chip.plain` 只读标签，点它按 `kind` 选资产中心的二级标签，并写 `#assets/<sub>/a<id>` 落到详情。`kind` 映射：角色 1、场景 2、道具 3。
- 作业列：无作业显示“未提交”；有则最新状态 chip＋“N 条 · #最新 id”，`title` 列出每条 `#id 状态`。没有按钮。
- 每行「生成」从 `shotCache` 取提示词（空则内容），经 navstate 交给生成中心，不在这页开第二个提交框。
- 两套主题都用令牌；夜间截图另存两张。

## 9. 边界（这一包不做）

- **不加景别／运镜／对白等列**：见 §3。
- **不写镜头级状态**：`shot.status` 列存在，但界面不写；作业八值状态才是执行真相。
- **不嵌播放器**：产物预览仍在生成中心详情抽屉。
- **不能拖拽排序／批量改**：镜号由创建顺序定。
- **没有 Task 实体**：一镜多作业靠 `job.shot_id` 反查。
- **不是画布**：没有节点、端口、连线。
