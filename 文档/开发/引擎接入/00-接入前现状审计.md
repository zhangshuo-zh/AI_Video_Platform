## 3. 与"引擎实例"这件事相冲的既有边界（必须先认清，别实现到一半才发现）

1. **规格不入库**。〔代码可确认〕`adapters.py` 模块头与迁移 0035 的注释都写着：参数范围、计价、出处一律住代码，页面只有"登记一个实例"，没有"新建模型规格"。登记弹窗的 provider／模型标识两个下拉的选项**只来自清单**，界面在 `fillPicks` 里就把清单外的值挡住。→ 任何 `engine_instance` 表都只能是"这一档在哪个端点"，不能变成第二个"什么能跑"。
2. **存在性现查、不落库**。〔代码可确认〕0035 对 `artifact_path` 的注释原话是"不校验存在性，存在性由 runtime.py 现查，不落库"。→ 实例表不该有 `health_status`／`detected_version`／`last_probed_at` 这类列；探测留痕的既有去处是 `model_validation` 的 `env_check` 事件。
3. **一个实体一个东家**。〔文档声称＋代码可确认〕0035 那次拒绝把任务场景塞进 `generation_profile`，理由就是这句。→ 工作流模板不得塞进模型规格，也不得与 profile 互相抄字段。
4. **remote 那一档还不接验证**。〔代码可确认〕`routers/model_center.py` 的 `_VERIFIABLE_BACKENDS = ("local","cloud")`，0021 的 `model_validation` CHECK 也只认这两值。→ 若把局域网里另一台机器上的 Comfy/Draw Things 登记成 `remote`，它**永远点不了环境检查**；要接得先扩验证表（独立改动）。
5. **远端仓库是公开的**。〔目标机实测〕GitHub `AI_Video_Platform` 自 2026-11-01 起 public，CI 日志同为公开面。→ 接入过程里任何本机绝对路径、模型文件名、服务端口都算信息暴露，日志与响应必须过 `describe_path` 那一层。

## 5b. 真调用实测（2026-11-06，〔目标机实测〕）

用户在 GUI 里开了 API Server（HTTP、端口 7860、绑定 127.0.0.1），并把模型切到导入的 noobaiXL。以下每条都有可复跑命令（见 §6 末尾）。

| 测项 | 结果 | 对 W-B 的含义 |
|---|---|---|
| 监听 | `DrawThings PID … TCP 127.0.0.1:7860 (LISTEN)` | 只绑回环：别的机器将来调不到，要跨机得改 0.0.0.0＋`sharedSecret` |
| `GET /sdapi/v1/options` | HTTP 200，2710 字节，**87 个扁平键** | 这 87 键就是参数白名单的一手出处，比 `strings` 硬 |
| 返回体随模型变 | 切到 noobaiXL 后 `width/height` 1024、`steps` 16、`sampler` `DPM++ 2M AYS`、`guidance_scale` 5 | **options 是"当前模型的默认值"，不是静态规格**——平台不能把它抄成清单，只能现读 |
| 模型键名 | `model = noobaixlnaixl_epsilonpred11version_f16.ckpt` | 换模型的字段叫 `model`，不是 A1111 的 `sd_model_checkpoint` |
| `POST txt2img`（512×512、4 步、seed 42） | HTTP 200，墙钟 **15.0s**，响应 533,598 字节，`images[0]` 解出 **合法 PNG**（魔数 `89504e47`、393,538 字节、`sips` 读得 512×512） | 端到端通了；产物是**响应体里的 base64**，不是文件路径，收集器要落盘再验真 |
| 响应体结构 | 顶层只有 `images` 一个键，`parameters`／`info` 都是空对象 | A1111 客户端常读的 `info` 在这里没有——外部读数只能自己算 |
| 未知键 | `bogus_key_zzz` → HTTP 422 `Unrecognized keys: ["bogus_key_zzz"]`，0.0s | 参数拼错是**当场拒绝**，不会被静默忽略（对我们是好事） |
| `sd_model_checkpoint` | 同样 422 `Unrecognized keys`（0.0s，用 128×128/1 步的最小代价试出来的） | **不能靠这个键换 checkpoint**，E 里那条 negative 证据由行为级确认 |
| 校验顺序 | 送 `width=64` 时先报「Width must be between 128 and 8192」，还没轮到未知键 | 范围检查在前；**128 是下限** ⇒ Draw Things 当不了缩略图／预览档 |
| `POST /sdapi/v1/options` | **HTTP 404** | **没有任何可编程的换模型入口**——选 checkpoint 只能在界面里做 |
| `GET /sdapi/v1/sd-models` | HTTP 404 | 没有 A1111 的模型列表端点；平台能读到的只有 options 里那一个 `model` 值 |
| 内存读数 | 生成前后 RSS 0.11 → 0.31 GB | ⚠️ RSS 低**不等于**没吃内存（MLX 分配不一定算在应用主进程里）；这一档不能拿去当容量规划，要量得像 `model_footprint_check` 那样沿子孙进程按秒采样 |

**由这张表得出的一个设计结论（要写进 W-B 的方案，不是实现细节）**：既然换模型只能靠 GUI，Draw Things 在平台里就不是"每条作业选一个模型"的引擎，而是"**一次会话只有一个当前模型**的引擎"。W-B 能做的只有三档，得由你选：一是把 `model` 当**引擎实例的状态**读出来，登记行与之不符就 blocker 拦住（不自动切，符合 MC1 的口径）；二是每个模型配一个独立实例记录，靠人手动切；三是先只做文生图这一档，模型固定，其余留给 ComfyUI。我倾向第一档——它最接近"引擎在线不代表模型可用"这句现成的话。
