## 1. P0-5 前端改了什么

| 文件 | 改动 | 为什么要这么改 |
|---|---|---|
| `js/modules.js` | 新增 `GROUPS` 五组分组与每个模块的 `group`；新增 `production`（项目工作台）；新增 **隐藏路由** `shot`（`hidden: true`） | 任务书 §11 要分组式导航；镜头工作台不能做成创作中心的第四个子页——那会和文档详情深链抢同一个 `sub` 参数位，做成独立隐藏模块才不会撞 |
| `js/store.js` | 加 `episodes / currentEpisodeId / loadContext() / selectEpisode()`；选项目时清集并回写上下文 | 当前集必须**住服务端**（`user_context`）：前端只记项目的话，换浏览器就丢，而"顶栏一个集、工作台另一个集"是这类改造最容易出现的自相矛盾 |
| `js/app.js` + `index.html` + `css/app.css` | 分组侧栏、顶栏集选择器、`toast()` | 选集要有可见反馈与失败回滚；失败回滚而不是乐观到底，是因为上下文写失败时页面显示的集和服务端存的集不能不一致 |
| `js/api.js` | 8 个新调用（上下文、生产总览、镜头工作台、资产影响、三类预检） | 与后端 8 条新端点一一对应，守卫表已钉 |
| `js/validation.js` | `PUBLIC_STATUS` 五档对外状态与 `publicStatus()` | §12.3：五个词给界面、细粒度留详情；后端状态语义一个都没合并 |
| `js/views/production.js`（新） | 项目工作台：四个数、九阶段表、下一步任务、各集进度、两个生产入口 | 数字全部现算自 `GET /api/projects/{p}/production`，页面不自己算第二份 |
| `js/views/shot-workbench.js`（新） | 单镜头八段工作台、设定弹窗、提交前预检拦门 | ⑤ 音频段**只给跳转不给提交**——执行未接线时给按钮就是骗人 |
| `js/views/writing.js` | 分镜每行加「工作台」按钮 | §12.1 减少无意义跳转 |
| `js/views/generate.js` | 提交弹窗先跑 `precheckShot`，阻塞不发、警告说在前面 | 防"弹窗说能提交、点下去吃 422" |
| `js/views/composition.js` | 新建成片弹窗内嵌合成前检查面板；阻塞时「开始合成」不发 | §9.2 要总数量与可定位 |

## 2. P0-6 验收工具与真跑结果

新增两个验收工具（都不是 pytest 的替代品，而是补 pytest 量不到的那一层）：

- `tools/production_scenario_check.py`：任务书 §17 六个场景，**53 项检查**。真 HTTP、真 worker 子进程、真产物、真 FFmpeg、真模型轨；跑 `/tmp/scenario_check` 库副本，开发库一个字节没动。
- `tools/production_browser_check.py`：两个工作台的真浏览器验收，**28 项**（含 380px 溢出与 JS 异常）。

逐场景结果与实测数字见 [03-业务验收记录.md](03-业务验收记录.md)。最值钱的两条：

1. **真实模型第一次跑通平台 Job**：产线节点派发 FastMetal 1.3B-QAD 出真 mp4（30.2s／640×352／234KB）；配上图像默认轨后重试那一格，mflux FLUX.1-schnell Q4 出真关键帧（174.1s／1024×1024／1.93MB）。都是平台自己的队列与 worker 执行的。
2. 六个场景里有五条"负向拦门"是真生效的：预检阻塞不提交、合成阻塞回 422、未签字不算正式产物、音频未接入不给按钮、云端结果未知落待核对。

## 3. 真跑照出并修掉的四个缺陷

| 缺陷 | 只有在哪里才露出来 | 修复 | 钉住的用例 |
|---|---|---|---|
| 对 `sqlite3.Row` 调 `.get()`（引用形态的镜头开工作台就 500） | 数据形态齐（资产＋形态）＋走 HTTP | `production.py` 改按键取并容下父资产缺失 | `test_shot_workbench.py::test_引用形态的工作台不能因为父资产是Row就炸` |
| `review.pending` 把 Row 放进响应（`PydanticSerializationError`） | 有成功但未签字的视频作业＋走 HTTP | pending 改成普通 dict，前端同步改字段名 | 同一条用例的后半段（坚持用 client 而不是直调函数） |
| `runners._fastmetal` 不读清单默认值，空参数作业丢掉 `--fast-spatial` | 产线节点那种 `params={}` 的真提交 | 新增 `_spec_default()/_flag()` 回落清单，显式 false 不硬塞 | `test_runners.py::test_fastmetal_空参数也照清单默认开fast_spatial` |
| 云端错误码双前缀（`provider_provider_unavailable`）让"结果未知"伪装成"失败可重试" | 云端 5xx **且带回执 id** | 先剥重复前缀再拼，与 `CLOUD_UNCERTAIN_CODES` 共用一套命名 | `test_cloud.py::test_云端5xx带请求ID时进待核对而不是普通失败` |

顺带补的两处（不是缺陷，是缺口）：预检第⑦项 `artifact.source_stale`；假适配器 `media=mp4/png` 一档，让"签字→取片→合成"这条链在真跑里不断在产物上。

## 6. P1 已起步：第 7 项「异常恢复机制」

P0 收口后按任务书顺序进了 P1，先做的是 §14 那条最贵的：

- 新增 `error_catalog.py`（40 条目录项，每项七个字段齐：可懂说明／技术详情／影响范围／推荐做法／可否重试／是否可能额外收费／是否需要人工），§14 点名的十二类异常按标题逐类对得上。
- 新端点 `GET /api/jobs/{id}/diagnosis`（权限点仍走 `job:read`，不给它开第二条更宽的出口）；生成中心的作业抽屉多出「这一条为什么这样，接下来怎么办」一栏。
- 三条纪律：目录**只翻译不判命**（判定仍只住 `worker.CLOUD_UNCERTAIN_CODES`／`services`／`adapters`）；认不出的码必须 `known=False` 并原样带出执行器的话；`retryable` 这一栏对云端结果未知与被驳回的产物一律关死。
- 写的时候当场修掉一处会把界面变成"狼来了"的判命：排队／执行中的作业 `error_code` 本来是空的，空码去查目录会命中"未登记的错误码"——现在这两种状态各有实话条目。
- 测试 **832 → 844 passed**（新增 11 项）、守卫表 +1、`make_release_baseline.py --check` 通过（844 passed／业务端点 162／总 167／迁移 0037）。

**真浏览器渲染已补上**：`tools/production_browser_check.py` 扩到 **34/34**，点队列里一条 `mock_failed` 的作业就能看到那七栏与三个判断章；因为 `mock_failed` 是刻意不登记的码，这一屏同时证明目录"认不出就承认认不出、不给可直接重试"。
