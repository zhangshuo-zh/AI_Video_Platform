## 1. 一句话结论

统计不回答"该做什么"，只回答"跑到哪、花了多少、还差多久、这一条占了多少内存"——**四个数都能指回具体哪几条作业**。指不回的（该重做哪一镜、推荐换哪一档）不摆，并且把"为什么不算"占一行写在屏上。

## 2. 做了什么

| 项 | 落点 | 出处纪律 |
|---|---|---|
| 生产统计面板 | 项目工作台原有那一页下方的卡片，读 `GET /api/projects/{p}/production` 新增的 `stats` | 金额取 `jobs.cost_summary`（与成本账同一条 `BILLABLE_WHERE`），不在统计里重抄 WHERE |
| 条数与状态分布 | `jobs.stats_for_projects()`：状态×能力如实数 | 界面不合并成"完成率"；没签的多少由作业状态回答，不与签字数拼一个比例 |
| 平均耗时 | 同上，`timed` 只算量得出耗时的那些条 | 把排队中的条算进分母会得到一条假均值 |
| 原因排行 | 错误码分布，中文名取自 `error_catalog.lookup()` | 码表不再抄一份；目录说「未登记」就显示未登记 |
| 内存读数 | worker 每条作业起采样线程（`_RssWatch`／`descendant_peak`），写 `child_peak_rss_sampled_kb` | 与 `child_max_rss_kb`（worker 生命周期值）两种语义分开留存；没读数的能力显示「没读数」 |
| 推算与并行参考 | `estimate`（下界＋若全新提示词的上界）、`memory.parallel_reference`（连算式一起给） | 没有样本给 None；0.8 余量口径写进字段，不藏进代码 |
| 盘余估算 | 新增 `diskplan.py`＋`jobs.recent_result_paths()`，四个入口与统计面板改读它 | 每镜平均不许被一次成片污染；没有样本只说固定提醒线；算式与 1.25 系数写进文案 |
| 签字结论标签 | `js/validation.js` 新增 `DECISION_LABEL`／`DECISION_TONE`，审核中心删掉自己那份 | 同一句中文名只住一处 |
| 批量重投卡住的镜头 | `POST /api/jobs/retry-batch`＋`services.job_retry_batch()`＋`jobs.latest_jobs_by_shot()`，按钮在项目工作台「下一步」卡片里 | 只重投本机 `failed`／`cancelled`；云端与 `needs_attention` 逐条拒并写明原因；上限 50 条不静默截断；每条走与单条同一个 `jobs.retry()` |

## 3. 真实环境的测量（本轮取证的地基）

| 事实 | 实测 | 工具 |
|---|---|---|
| 整集 6 镜真实模型连跑 | 14/14 全过；单镜 avg 32.8s、每条 640×352／5.06s；六条逐条签字后合成 30.38s 成片，与素材合计差 **+0.00s** | `tools/episode_real_run_check.py` |
| 冷／热提示词 | 新提示词编码 82.0s、本条峰值 8.75GB；同一条第二次 0.007s、1.99GB；两次独立复现（33.9s vs 114.9s） | `tools/model_footprint_check.py` |
| 图像档 | mflux FLUX.1-schnell Q4 1024×1024 4 步 202.8s、采样峰值 3.13GB | 同上 |
| 旧内存字段会串台 | 一条实际 3.13GB 的图像作业被记成上一条 8.75GB 视频的峰值 | 现场发现→新增采样字段 |
| 新字段端到端 | 库里 `child_peak_rss_sampled_kb = 2,086,496 KB`，与外部采样器独立量到的 1.99GB 一致 | `GET /api/jobs/{id}` 与副本库读回 |

所有金额、尺寸、时长、内存都是现量，不引推算值；跑在库副本（`/tmp/episode_run`、`/tmp/footprint_check`），开发库未动，`model_validation` 一条没新增。
