## 已修复

### 1. 指定资产的生成历史被其他资产挤掉

触发：资产 A 生成成功后，同项目资产 B 又产生超过 `limit×4` 条生成记录，刷新 A 的创作页。

入口与位置：`GET /api/projects/{project_id}/asset-generations` → `asset_studio.recent_generations` → `repositories/jobs_parts/query.py:recent_asset_generations`。

原实现只按 `op:` 前缀下推，先取固定窗口，再按目标资产筛选。现在项目、合法操作与目标资产全部在 SQL WHERE 中判定，然后按 Job id 倒序取 limit。共享解析器移至 `asset_generation_refs.py`，`asset_studio.parse_refs` 的既有调用方式保留。通过连接局部的确定性 SQL 函数复用原解析语义，避免 JSON 空白、旧引用顺序、前导零、重复引用与脏项处理出现第二套答案。不增加字段、索引或迁移。

回归覆盖：真实 HTTP 查询、55 条其他资产作业、跨项目引用、仅 ID 前缀相同的引用、旧格式及格式化 JSON、合法与未知操作、重复引用、坏 JSON，以及 limit=1 的稳定排序。修改前 HTTP 返回空列表，修改后正确返回 A 的历史。

取样：临时库真实执行全部迁移，2001 条成功作业（目标资产 1 条，其他资产 2000 条），同条件各测 30 次。旧实现返回 0 条、中位 2.485 ms；新实现返回目标 Job #1、中位 2.927 ms。两者均一次 SELECT，计划均使用 `idx_job_project` 并使用临时 B-tree 排序，无写事务。此项修复漏查，不宣称性能提升；归属解析仍随项目历史规模增长，本次数据不支持新增迁移或索引。取样脚本与结果：`.out/backend-tuning/benchmark.py`、`benchmark.json`。

### 2. 云端取消分支异常，无法正常收尾

触发：Worker 已拿到供应商请求 ID，用户取消；供应商可能确认取消、已在运行而拒绝取消，或取消接口网络失败。

位置：`worker.process` 的 Cancelled 分支；`job_state.TRANSITIONS`。

缺陷一：实际领取返回 `sqlite3.Row`，分支调用 `job.get()` 抛 AttributeError。改为列名读取。缺陷二：供应商未确认取消时，Worker 已有转待核对逻辑，但状态机未允许 `cancel_requested → needs_attention`，继续抛 ValueError。补齐该转移，终态写入仍须通过原 Worker 归属守卫。

回归从 `worker.run_once` 真实领取进入 `process`，只模拟执行器及供应商取消响应。三种结果分别核对一次取消调用、准确状态、请求 ID、原预计成本和执行者释放。先修第一处后，确认取消分支通过，其余两支仍报状态机错误；第二处修复后全部通过。

### 3. 无请求 ID 的未知云端结果被误判为普通失败

触发：供应商已收到请求，但回执前断线；或网络超时、响应损坏；或云端 running / cancel_requested 状态下租约失效，请求 ID 尚未落库。

位置：`worker.CLOUD_UNCERTAIN_CODES`、`worker._cloud_uncertain`、`worker.process`、`repositories/jobs_parts/lease.py:recover_stale`。

现在网络、超时和受理后断线等未知结果不再以“有请求 ID”为待核对前提；补入真实断线得到的 `provider_cloud_run_error`。失效的云端 running 与 cancel_requested 也先进入 needs_attention，保留账目，避免被编排当成普通失败继续重试。明确的鉴权失败仍为 failed。执行前取消没有执行规格与请求 ID 时仍可直接 cancelled；未执行且无请求 ID 的 starting 租约失效仍可 failed。

兼容取舍：cancel_requested 没有保存取消前是 starting 还是 running，租约失效后不能证明供应商未受理，因此保守要求人工核对。可能增加少量其实未发出请求的核对工作；不把未知金额自动算成零。两条旧测试曾把“无请求 ID”解释为“供应商未被调用”，已修正断言及解释。

验收：本机假 HTTP 供应商记录 POST 后直接关闭连接，真实云端子进程与 Worker 完整运行，最终 needs_attention、请求 ID 为空、仅一次 POST；再跑 Worker 不重发。另覆盖有请求 ID 的 5xx、鉴权失败，以及无 ID 的网络错误和超时。模拟计费作业的原成本保留，未修改真实账单。
