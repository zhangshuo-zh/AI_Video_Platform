## 2. 三处必须先裁的冲突

### 冲突一：「添加模型」要写库，第十五条禁「复制一套新的模型清单」

清单（`adapters.py`）是规格：参数范围、倍数、互斥、计价、出处、核验日期，`validate_params()` 与 `health()` 都读它。让它变成库表＝把安全边界交给页面输入框，且出处与核验日期这种"人核过的事实"没法靠填表产生。

**本方案的解法（已定，除非你否）**：规格与实例分层——

- `adapters.py` 继续是**规格的唯一来源**，页面只读，不入库、不可编辑；
- 新增 `model_registration` 表存**这台机器上的模型实例登记**：显示名、来源、引擎、版本、权重路径或远程模型 ID、启停、备注；
- 「模型仓库」页＝清单 LEFT JOIN 登记。清单里有、没登记的档显示「未登记」；登记了、清单里没有的显示「清单未登记，参数不猜」。

这样"添加模型"添加的是实例引用，不是第二条清单；第十五条不被违反。

### 冲突二：备用方案要不要真的自动顶上（**待你裁**）

任务书 §七 规则 3 写「资源不足时应提示、排队或使用经过授权的备用方案」，规则 4 写「不得静默切换到能力不兼容的模型」。现有不变量是《需求概要说明书》§4.10.1 与《系统设计说明书》§1 的**路由不补位、不兜底**：默认轨没配好就报错，绝不偷偷换轨（`services.py:1405` 抛 `NoRoute`）。

规则 4 与不变量一致；规则 3 的"使用备用方案"越过了它。三个选项见提问框。

### 冲突三：本轮要不要接 ComfyUI / Draw Things（**待你裁**）

任务书 §六 点名这两台引擎，但平台里零引用。接 ComfyUI 意味着 HTTP 服务地址、workflow JSON 契约、队列查询、产物回读四件事；接 Draw Things 意味着先证实它到底暴露哪些本地接口（§六.2 自己就警告"不要假定 Draw Things 一定提供所需 API"）。**这两件各自是一个独立工作包，塞进本轮会把 P0 变成两个月。**

另外提醒一条纪律：本机装了 ≠ 平台能调。引擎管理页里它们必须以「未接入」出现，不能因为 Demo 画了绿点就画绿点。

### 8.1 MC1 裁甲之后的能力声明口径（随裁定定稿）

任务书 §5.1 禁"仅根据模型名称自动推断能力"，所以标签只有两个合法来源，界面上分标显示：

1. **清单派生**（可查、可复算）：`接收参考图` 来自 `ModelSpec.image_inputs`（它本身是从已登记的参数里数出 `type=="image"` 得来的，`adapters.py:113`）；`可调参数 X`、`按秒计价` 来自 `params`/`prices`。
2. **人工声明**（`model_registration.capabilities_json`）：由管理员填，界面上必须带「人工声明 · 未核验」字样；只有当这一档存在 `real_call` 或 `artifact_review` 的 `model_validation` 记录时，才允许显示成「已验证」。

模型名里带 `i2v`/`t2v` 不构成能力证据，界面上不把它翻译成"图生视频"标签。
