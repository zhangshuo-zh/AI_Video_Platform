## 1. 大规模项目作业历史

通过 `tools/asset_history_benchmark.py` 在临时库执行真实迁移，构造同项目 100000 条成功图像作业，每十条中一条属于资产 1，分别读取项目历史、资产 1 历史与不存在资产的历史。每类重复 5 次，逐项比较前后 Job id，查询结果完全一致。

原索引 `(project_id,queued_at DESC)` 不能满足 `ORDER BY id DESC`，计划包含临时 B-tree 排序，并在取 limit 前解析项目内所有引用。新增迁移 `0053_job_project_id_index.sql`，只增加 `(project_id,id DESC)` 索引。原查询、旧引用解析、可见项目条件、稳定返回顺序均未改变。

本轮最终取样结果（`.out/review-import-fixes/final-history-load.json`）：

- 项目最近历史：中位 120.953 ms → 0.600 ms。
- 活跃资产最近历史：119.520 ms → 0.700 ms。
- 不存在资产：118.505 ms → 133.700 ms，仍须扫描，不能宣称所有资产查询恒定耗时。
- 查询计划：由 `idx_job_project` 加临时排序，变为 `idx_job_project_id`，无临时排序。每次读取仍为 1 个 SELECT、无写事务。
- 10 万条数据建索引约 20.087 ms。1000 行批量插入并回滚的中位写锁范围取样为 137.011 ms → 136.849 ms；不据此宣称写入加速。

旧版库升级回归：临时库先执行到 0052、插入作业及旧引用，再升级。只执行 1 个迁移，Job 全行数据不变；再次迁移为 0 个。验证自动备份保留升级前的 0052 版本、原数据且不含新增索引。需要回退时停机使用该备份，或仅删除新增索引；不删作业数据。

## 2. 图片导入进程中断后的持久化恢复

新增 `app/backend/asset_import_recovery.py`，在原导入写入口中接入，不创建第二个图片记录写入所有者。

流程：路由持有原 `BEGIN IMMEDIATE` → 写入并落盘导入意图 → 复制图片并同步文件与目录 → 更新基础图或形态图记录 → 数据库提交 → 移除意图。意图只保存版本、目标相对路径和来源 Job ID，位于 `FILES/.asset-imports/`。

启动恢复在 `main.create_app` 的迁移之后执行。逐条取得与正常导入相同的 SQLite 写锁，在锁内重读意图和数据库引用：已登记的文件保留；有合法意图且确定未登记的文件清理；无意图的历史文件不扫描删除。基础图与形态图的引用查询集中在仓储 `assets.image_reference_state`。

可捕获异常仍立即补偿。若补偿删除因权限失败，HTTP 返回 503，明确告知已保留恢复记录；权限恢复后可以重启或运行工具重试。数据库已提交但意图清理失败时仍返回成功，下次恢复保留已登记图片，避免用户误以为失败而重复导入。

安全边界：拒绝越界记录、目标符号链接、恢复记录符号链接（含悬空链接）；遇到不确定的坏图片清单或已登记图片丢失时保留证据，报告 pending，不伪报恢复成功。

验证使用真实子进程 `os._exit(73)`，不依赖异常清理钩子：

- 基础图与形态图分别在复制后、行写入后但提交前退出：启动恢复清理未登记文件，原记录和原图保留。
- 基础图与形态图分别在提交后退出：启动恢复保留已登记文件及引用。
- 恢复重复执行不改变已收口结果。
- 两个独立连接竞争：导入暂停在复制点时，恢复实际等待写锁；导入提交后图片保留，不被误当孤儿删除。
- 基础图与形态图补偿无权限：503、无数据库新增图片、保留意图；恢复权限后启动清理，再次导入成功。
- 已提交意图清理无权限：200，重启后保留图片并清理意图。
- CLI 预览不删文件；--apply 只删本次未登记文件，保留无意图的历史文件。

本轮证明了真实进程突然退出后的恢复路径；未实际断电或模拟存储设备损坏。使用 fsync 持久化意图、图片和目录，不能据测试宣称任何存储设备上的断电保证。旧版本未记录意图的历史孤儿文件仍不自动删除。

## 3. 恢复工具使用

从仓库根目录运行，沿用当前配置；需要检查其他环境时先设置 `FASTVIDEO_DB`、`FASTVIDEO_FILES`。

```sh
app/backend/.venv/bin/python tools/recover_asset_imports.py
app/backend/.venv/bin/python tools/recover_asset_imports.py --apply
```

第一条仅预览，第二条实际恢复；存在 pending 或 invalid 时退出码为 1。工具不初始化数据库、不运行迁移；数据库不存在时直接拒绝，不创建空库。不对现役库执行本轮故障注入。
