## 1. 一句话结论

说明书要的**四件事里三件已经能用**：配置与健康的统一入口、任务类型路由（复用模型中心那九行）、Run/Step/Event 的运行记录与白名单工具回路、以及"写操作先审批、执行后验真实状态"这条治理线。平台**没有**新建第二份配置表、**没有**新建第二条队列、**没有**新建第二个签字入口、**没有**新增一个权限点。〔代码可确认〕

真正没闭合的是一件事：**"真模型算出来的计划"从来没在这条线上跑过一次**。队列、解析、审批、执行、验收全部由假接口与手工数据跑通，本地 Ollama 的能力是单独实测的（第 5 节），两者还没接起来——这是下一轮的第一件活，不是已完成项。

### 验收过程中撞出来并修掉的四处（都不在原计划里）

1. **`addEventListener('click', run('取消', …))`**：`run()` 自己会立刻执行并返回 Promise，把它当监听器挂上去＝一进页面就把暂停／恢复／取消各发一次。是浏览器验收把运行"自己取消"了才追出来的——这类缺陷加载期看不见，只能靠真点。四处改法统一成 `() => run(...)`。
2. **`probe()` 缺第三个参数**：`EngineStatus` 是 frozen dataclass、`values` 没有默认值，"没有启用中的实例"那一支从来没被走到过；接 Ollama 第一次走到就 `TypeError`。补了参数与一条专门的红。
3. **计划失败看不见**：`run_status()` 只看步骤与 Job，"作业成功但产物不是计划"这种失败会永远停在"在算计划"。给 `agent_run` 加了一列 `plan_status`（pending／ready／failed）——它存的是**计划的落定结果**，不是 Job 状态的副本。
4. **验收自己污染了别人的用例**：智能体测试排队的付费作业与登记出来的资产，会让看板的"这个项目恰好一个资产／还没有一笔账单"变红（单独跑绿、全量跑红）。改成自己的项目自己用，收尾再把 worker 心跳与排队作业收干净。

## 5. 本地文本腿的真模型实测

〔真模型实测〕全部 2026-11-06 本机：Apple M4／16 GB／盘余 171 Gi，Ollama 0.35.1（`/api/version` 现读），在册模型只有一个：

| 读数 | 值 | 出处 |
|---|---|---|
| 模型 | `qwen3:8b`，8.2B，Q4_K_M | `GET /api/tags` |
| 权重大小 | 5,225,388,164 字节 | 同上 |
| 上下文 | 40,960 | 同上 `details.context_length` |
| 声明能力 | `completion`／`tools`／`thinking` | 同上 `capabilities` |

三条决定实现方式的实测结论：

1. **工具调用是真的**：带 `tools` 发一次 `/api/chat`，返回 `tool_calls:[{name:"list_missing_assets", arguments:{episode_seq:1}}]`，耗时 16.3 秒（其中模型加载 5.7 秒、生成 176 token）。
2. **结构化输出必须把思考关掉**：带 `format`（JSON schema）而 `think` 缺省时，300 个 token 预算全部花在推理上、`content` 是**空的**——作业会"成功"并留下一个空产物。同一请求加 `think:false` 后 1.9 秒、29 token、返回合法 JSON。这条直接写进了清单默认值（`ollama` 那一档 `think` 默认 false）和 `llm_http_run.py` 的强制逻辑。
3. **OpenAI 兼容面也能用但更慢**：`/v1/chat/completions` 配 `response_format` 27.7 秒返回，且结果比原生面少抽出一项。所以平台走 `/api/chat` 原生形状。

一条真作业的闭环〔真模型实测〕：登记一条 ollama 引擎实例（临时）→ `runners.build()` 出子进程 → `llm_http_run.py` POST → 4.0 秒落盘产物 `[{"name":"燧人"}]`，回执带 `usage.eval_count=9`、`prompt_eval_count=31`、`think:false`、`has_format:true`。临时实例随后撤掉，没在开发库里留下行。

**没测的部分要说明白**：真实模型**算出来的**计划（多步、带工具码）没有在这条线上跑过一次——本轮所有计划都来自假接口或手工数据。本地 8B 在这一题上的稳定性没有统计量。

## 7. 没做什么（开口）

1. **真模型算计划没跑过**（第 5 节末）。要闭合需要一次真调用：本地 ollama 或云端 deepseek 各一次，产物进 `agent_run.plan_json` 并核对步骤数。
2. **「每次询问」这一档路由**：说明书 §3.3 明列，`model_policy.preference` 没有这个取值，扩它要改 CHECK（又一次整表重建）。
3. **预算上限**：只有"逐次确认单"，没有"这个月这个项目 Agent 已花多少、到线就停"。成本账在生成中心那一侧是齐的，缺的是**按 Agent 维度汇总**。
4. **步骤级重试**：失败步骤只能靠重新发起整条运行。产线有单节点重试，这里刻意没抄——抄来就要回答"重试算不算一次新的审批"。
5. **驻留／空闲卸载／资源保护**（第 6 节 §3.1 那行）：服务型引擎不归平台管，这条边界要人认可才算落定；如果真要"视频生成期间压低 Agent 常驻优先级"，那是 worker 的并发闸门那一轮的活。
6. **文档与截图**：本册只记交付事实；《系统使用说明书》里的智能体中心那一章需要真界面截图，截图要与"默认轨到底走本地还是云端"定下来之后一起拍，否则一页两张图互相矛盾。
7. **开发库配置没替人改**：`engine_instance` 里 ollama 那一行、文本×本地 设为默认轨、`model_registration` 里 `ollama/qwen3:8b` 的登记行——本轮**一条都没写进开发库**。这是"要花钱／要改默认行为"级别的选择，留给人点。要本地优先跑通，需要这三下都在「模型中心」里做。
