# 平台整体审查与优化建议

- 状态：历史留档（2026-11-12 工作区审查快照，后续修复以代码为准）
- 当前口径：架构见《系统设计说明书》，可复算读数见 [发布基线](../../发布基线.md)。

日期：2026-11-12。范围：当前工作区（包含尚未提交的引擎检查弹窗修改）。

本轮为面向后续改代码的审查记录，没有修改业务代码。采用核心路径静态阅读、模拟接口浏览器复现、四组后端隔离测试；不等于所有页面已手工验收，也不等于安全或并发的全量审计。历史报告里的问题未直接当作本轮现存缺陷。

## 总体判断

保留 FastAPI、SQLite WAL、原生 ES Module、独立 worker 的架构。按 README 的 2–5 人部署规模，目前没有证据支持改成微服务、引入 Redis 或整体迁移前端框架。现有事务封装、后端权限守卫、生成队列、默认选路、统一签字入口及 CI 应继续保持。

优先治理编辑状态、异步请求顺序、幂等提交和浏览器行为验收。界面优化放在这些基础之上，否则会继续出现页面好看了但状态不可信的问题。

## 第一批：数据和操作结果可信

### 1. 高优先级：保存期间继续输入，被错误标为已保存（浏览器已复现）

位置：app/frontend/js/views/writing.js:569–578。

保存请求发送 ta.value，等待后又读取当时的 ta.value 写入 draft，并无条件 setDirty(false)。输入框在请求期间仍可编辑。

复现：提交正文 submitted；请求未返回时输入 typed while saving；返回成功。实际发送 submitted，输入框是 typed while saving，提示却为“与盘上一致”。关闭窗口保护随之失效。

建议：冻结提交文本和编辑修订号；成功只确认该次快照，期间有新增输入则保留 dirty；异步响应更新前核对文档 id 和编辑会话，防止晚响应覆盖另一份稿件的模块状态。

验收：延迟保存响应，继续输入，新内容仍显示未保存；再次保存后才变为一致。

### 2. 高优先级：草稿保护没有统一覆盖所有入口（代码确认）

位置：app/frontend/js/views/writing.js:195–213、429；app/frontend/js/app.js:115–133；app/frontend/js/store.js:150 起。

页内文档类型切换有确认，侧栏直接 setSub + goView，项目切换直接改 store。renderDocs 选择新文档后，会用新正文覆盖唯一的 draft 并清 dirty。因此项目切换、侧栏切换到另一类正文仍可能丢掉未保存内容；beforeunload 只处理浏览器离开，不会处理这些 SPA 内部动作。

建议：导航/项目/集切换先经过统一编辑会话守卫，再修改上下文。支持保存后离开、丢弃、取消；草稿按用户/项目/文档标识保存恢复，持久化方案需考虑共享电脑和退出登录的清理。

验收：页内、侧栏、项目切换、详情跳转均验证取消后原文不丢、上下文不变。

### 3. 高优先级：集切换失败回调可覆盖更新的选择（浏览器已复现）

位置：app/frontend/js/store.js:131–143；app/backend/routers/production.py:56 起。

selectEpisode 没有序号校验。当前集 10，连续选 11、12，第一次请求晚失败会将当前集回滚为 10。模拟接口实测 expected=12，actual=10。

项目切换 select 的序号只保护前端回调，不能控制已发送 setContext 在服务端的提交顺序；这是另一个需验证的持久上下文风险，不应把当前序号保护当作完整解决。

建议：统一上下文写入调度，保护前端回滚；同一客户端写入串行/合并，或者增加服务端版本条件。明确跨浏览器会话的上下文策略。

验收：快速 A→B、先请求后返回、旧请求失败、途中切项目，都不能回滚最新选择；刷新后上下文与最后一次有效操作一致。

### 4. 高优先级：幂等能力存在，但前端接入不一致（代码确认）

位置：app/frontend/js/views/generate.js:1523–1640；app/backend/services/jobs.py:250、356–370；app/frontend/js/views/agents.js:615–628；app/backend/services/doc_ai.py:89–164。

更正此前判断：后端通用作业已经有 idempotency_key 与唯一约束兜底，不需要从零实现服务端幂等。缺口是生成中心没有传键；超时提示之后 finally 又放开提交，因此重复点击仍可能建重复作业。

智能体使用“项目 + 当前秒数”生成键：一次操作跨秒重试会变成新任务，同项目同秒的不同操作又可能共用键。文档 AI 直接建 job，缺少同等幂等保护。

建议：为每次逻辑提交生成随机稳定键；未知结果重试复用键；修改输入后显式开启新提交；服务端比较请求指纹，键相同但参数不同返回冲突。提供提交状态核对，减少人工翻列表。

验收：服务端已入库但响应丢失后重试只返回同一作业；不同操作、不同用户不意外合并。

## 第二批：交付验证和公共组件

### 5. 中高优先级：弹窗改动与已有浏览器门禁脱节（代码确认，尚未执行整套门禁）

位置：tools/model_center_browser_check.py:874–889；app/frontend/js/views/models/engines.js。

已有脚本仍断言“本次现查”“不等于”“0.8”“路通、钥匙被接受”等旧文字；新弹窗已经修改或移除这些文本。这些断言与当前实现不匹配。43 模块加载通过只证明导入正常，不证明启用按钮可用、列宽正确或弹窗操作成功。

建议：保留检查范围语义断言，使用稳定数据属性验证状态、按钮、请求参数和结果；补全部正常/已停用/连接失败/启用失败/启动失败/重新检查场景；校验实际 computed style 和元素边界，并保留宽屏、窄屏、双主题截图。

验收：更新后的浏览器门禁通过；启用失败仍保留弹窗，成功后状态更新；操作列显示条件正确。

### 6. 中优先级：CSS 需要统一语义变量与作用域（代码确认）

位置：app/frontend/css/app.css:2351、2355–2356；表格通用规则:2326–2331。

新弹窗使用 var(--text)，但当前样式表定义的是 --ink 系列，未定义 --text。这些颜色声明会失效并依赖继承；重新检查的强调色又使用固定金色，需检查明暗主题一致性。此前操作列宽度未生效，也来自通用表格规则与页面规则的优先级竞争。

建议：沿用 --ink/--accent 等现有变量；为诊断弹窗建立独立表格、footer 和按钮变体，避免继续靠加长选择器争优先级。固定操作列可由 colgroup 明确声明。逐步抽出基础组件与页面样式，保持加载顺序可预测。

验收：双主题文字对比、按钮 hover/focus/disabled、两列/三列、320–1440 CSS px 宽度下无溢出。

### 7. 中优先级：明确视图生命周期，降低整页重绘成本（结构建议）

位置：app/frontend/js/router.js:184–185；app/frontend/js/app.js:762 起；各页轮询实现。

当前通过整个 root.innerHTML 替换页面，再恢复焦点/滚动；多个模块分别维护 timer、visibilitychange、请求序号和判活。这已经有防护，但新增页面时容易漏一个出口。

建议：视图约定 render/mount/dispose；订阅、定时器、请求取消统一登记回收；编辑/弹窗内容不随状态轮询重建，只更新队列计数和对应行。先在生成中心、创作中心试点，保留无构建前端。

验收：反复换页后监听和轮询不累加；输入法组合输入、文本选区、弹窗表单在刷新中保持稳定。

## 第三批：全平台体验收敛（设计建议，需页面验收）

1. 工作台围绕当前项目、当前集、阻塞项和下一步操作组织；详细统计来源说明收进帮助，主要位置留给任务。
2. 导航维持工作台/准备/生产/交付/平台能力分组，优先提供上下文直达，减少让用户判断去哪个中心；不重复建立提交或审核入口。
3. 明确空状态、加载、加载失败、数据过期四种状态。网络失败不能简单显示成“没有数据”或“worker 离线”。
4. 统一弹窗宽度档、正文密度、footer 规则与主要操作数量；诊断用详情展开，编辑用稳定表单。
5. 动画优先承载任务完成、保存确认和错误反馈；保留已有减少动态效果支持，不增加高频整页入场。检查实际帧率后再决定是否简化扫光、持续闪烁等效果。
6. 前端大文件按职责渐进拆分：generate.js 约 2101 行、writing.js 约 1968 行、projects.js 约 1370 行（本次工作区统计）。先隔离编辑会话/提交状态/轮询组件，避免为了拆文件改业务。
