1. 黄金样例

1.1 样例包

每次发布后按这一套东西原样跑一遍，跑通了才算发布完成。内容是原创的微型故事，只有三镜，本地预览档几分钟内能跑完。

剧本（创作中心 → 文档，约 300 字，保存后记录 Git 版本号）：

> 《修伞匠》 > 雨下了三天。巷口的老人还坐在他的摊子后头，面前摆着三把断伞。 > 镜一：雨巷全景。青石板反着光，修伞摊缩在屋檐下，老人戴着老花镜低头理伞骨。 > 镜二：手部特写。粗糙的手指捏着细伞骨，铁丝在指间绕了两圈，收紧。 > 镜三：中景。少女把一把修好的伞递回来，老人接伞，抬头笑了一下。雨还在下。

1.2 八步执行手册

  1. 建项目与剧本：项目中心新建项目 → 创作中心建文档《修伞匠·剧本》，粘贴 1.1 的剧本并保存。记录文档版本（Git commit 号）。界面见《系统使用说明书》§4 与 《系统使用说明书》§6.2。
  2. 抽取：创作页对该文档发起文本抽取 → 抽出候选后逐条看原文证据，人工确认。当前版本不会自动把抽取结果变成正式分镜，确认后仍要手工建镜头。界面见 《系统使用说明书》§6.4。
  3. 建资产与镜头：资产中心建 2 项资产并传参考图 → 创作中心建 3 条镜头，关联资产。逐条检查提示词和参考图是否对得上。界面见 《系统使用说明书》§5 与 《系统使用说明书》§6.5。
  4. 提交生成：生成中心选本地预览档提交。提交前确认路由、参数快照、费用提示；本地不花钱，云端档必须逐次勾计费确认。界面见 《系统使用说明书》§7。
  5. 查产物：作业抽屉看产物文件、大小、时长、分辨率与 sha256；确认产物挂在对的镜头上。看不过眼的进「验证记录」登记产物验收结论。界面见 《系统使用说明书》§7 与 《系统使用说明书》§3.1（五档出处与验收结论）。
  6. 音频：配音/音乐三个运行时（VoxCPM2、ACE-Step、口型对齐）装好之前，界面显示未验证就是未验证，不在样例里假装跑过。装好后这一步补真实调用。界面见 《系统使用说明书》§9。
  7. 审核与导出：审核中心过 gate 报告 → 人工签字 → 项目看板导出镜头清单。界面见 《系统使用说明书》§8 与 《系统使用说明书》§11。
  8. 备份恢复：按 §2.3 的三条命令做一次备份 → 校验 → 恢复到临时目录，确认项目、文档 Git 历史、Job 和产物引用都还在。命令与运维口径见《系统设计说明书》§14。

1.3 验收标准

每个结果都要能一路追溯到：输入文档版本 → 镜头 → 资产 → 模型档 → 参数快照 → Job → 费用 → 审核结论。任何一步失败，要能说出失败发生在哪一步。八步全部留下记录，这套记录就是这次发布可以复现的证据。

2.4 两个状态不是一回事

job.status=needs_attention 说的是作业需要人处理；billable_status=pending_reconciliation 说的是费用待核对。云端作业可以同时占这两个标记，也可以只占后者（比如回执成功但账单没核对）。演练 2、3 的输出把这条界线跑实了：挂待核对时费用快照不动，核对时实际金额单独入账。

现库事实（2026-11-02 只读盘点）：job 共 13 条（succeeded 11、failed 2）；其中 #37、#38、#39 三条云端文本作业 succeeded 且 pending_reconciliation——这正是评审说的"预估金额不能当实际费用"的活样本，要等人在 DeepSeek 后台对出真实账单后走核对，平台不自动消掉它们。

量出来的三件事（每一件都改了文档里的说法，不是补充说明）：

  1. 冷／热提示词差 80 秒与 6.7GB。 同一条提示词第二次编码 0.007s、本条峰值 1.99GB；全新提示词编码 82.0s、峰值 8.75GB（本机 16GB 的 48.6%）。机制在 FastVideo 的 prompt_cache，缓存目录 ~/.cache/fastvideo/prompt_embeds。两次独立跑都复现（33.9s vs 114.9s）。所以统计面板的推算给区间，并把「按哪几条算的」写在同一行。

2.22 批量重投卡住的镜头（P2「批量制作」，实测 2026-11-05）

种数据的方式与本轮前几节同一套壳：一条注定失败的假适配器作业挂在第 1 镜、一条会成功的挂在第 2 镜。于是这一集的形状是"一镜卡住、一镜有片"，正好用来验批量入口的取舍——不是验它能不能点。

五条断言（整套 70/70）：

  1. 那颗钮只在"有待重投的镜头 ∧ 账号可写"时出现，标题带着条数（实测显示 重投卡住的镜头（1））。零失败或只读账号时不摆，点了必吃 403 的按钮不该存在。

  3. 结果条把逐条原因原话显示出来：重投 1 条、跳过 1 条（这一集共 2 镜有记录）｜跳过原因：镜 …：这一镜最新的作业已经成功，不需要重投。第一版这句话直接写进 DOM，被随后的 app:refresh 擦掉，检查读到空串——反馈必须活过一次重绘，于是改成模块级状态、并按「项目 × 集」失效。
  4. 真多排了一条作业，且它认得出自己是重投：新行 retry_of_job_id 指回原行（实测 #72 ← #70），attempt 加一。
  5. 原行的账不动：被顶掉那一行仍是 failed、错误码仍在，队列里仍查得到（重投不是抹历史）。
