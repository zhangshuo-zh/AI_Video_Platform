1. 黄金样例

1.1 样例包

每次发布后按这一套东西原样跑一遍，跑通了才算发布完成。内容是原创的微型故事，只有三镜，本地预览档几分钟内能跑完。

剧本（创作中心 → 文档，约 300 字，保存后记录 Git 版本号）：

> 《修伞匠》 > 雨下了三天。巷口的老人还坐在他的摊子后头，面前摆着三把断伞。 > 镜一：雨巷全景。青石板反着光，修伞摊缩在屋檐下，老人戴着老花镜低头理伞骨。 > 镜二：手部特写。粗糙的手指捏着细伞骨，铁丝在指间绕了两圈，收紧。 > 镜三：中景。少女把一把修好的伞递回来，老人接伞，抬头笑了一下。雨还在下。

资产（资产中心，2 项）：

资产类型说明
修伞老人角色参考图 1 张；一致性提示词：蓝布围裙、老花镜、灰白短发
雨巷场景参考图 1 张；一致性提示词：江南小巷、青石板、屋檐滴水

镜头表（创作中心 → 分镜，3 条，都关联上面两个资产）：

镜号景别生成档提示词要点
1全景本地预览（FastMetal 1.3B）雨巷、修伞摊、屋檐，参考图＝雨巷
2特写本地预览（FastMetal 1.3B）手部、伞骨、铁丝，参考图＝修伞老人
3中景本地预览（FastMetal 1.3B）递伞、接伞、笑，参考图＝修伞老人＋雨巷

1.2 八步执行手册

  1. 建项目与剧本：项目中心新建项目 → 创作中心建文档《修伞匠·剧本》，粘贴 1.1 的剧本并保存。记录文档版本（Git commit 号）。界面见《系统使用说明书》§4 与 §6.2。
  2. 抽取：创作页对该文档发起文本抽取 → 抽出候选后逐条看原文证据，人工确认。当前版本不会自动把抽取结果变成正式分镜，确认后仍要手工建镜头。界面见 §6.4。
  3. 建资产与镜头：资产中心建 2 项资产并传参考图 → 创作中心建 3 条镜头，关联资产。逐条检查提示词和参考图是否对得上。界面见 §5 与 §6.5。
  4. 提交生成：生成中心选本地预览档提交。提交前确认路由、参数快照、费用提示；本地不花钱，云端档必须逐次勾计费确认。界面见 §7。
  5. 查产物：作业抽屉看产物文件、大小、时长、分辨率与 sha256；确认产物挂在对的镜头上。看不过眼的进「验证记录」登记产物验收结论。界面见 §7 与 §3.1（五档出处与验收结论）。
  6. 音频：配音/音乐三个运行时（VoxCPM2、ACE-Step、口型对齐）装好之前，界面显示未验证就是未验证，不在样例里假装跑过。装好后这一步补真实调用。界面见 §9。
  7. 审核与导出：审核中心过 gate 报告 → 人工签字 → 项目看板导出镜头清单。界面见 §8 与 §11。
  8. 备份恢复：按 §2.3 的三条命令做一次备份 → 校验 → 恢复到临时目录，确认项目、文档 Git 历史、Job 和产物引用都还在。界面与命令见 §16。

1.3 验收标准

每个结果都要能一路追溯到：输入文档版本 → 镜头 → 资产 → 模型档 → 参数快照 → Job → 费用 → 审核结论。任何一步失败，要能说出失败发生在哪一步。八步全部留下记录，这套记录就是这次发布可以复现的证据。

2. 故障演练记录

演练脚本有两个，都是一条命令重放全部条目，只打临时库、不打真供应商、不花一分钱：tools/fault_drill.py 是七条 Job 与队列演练（§2.2），tools/pipeline_fault_drill.py 是十条产线编排演练（§2.6）。

app/backend/.venv/bin/python tools/fault_drill.py
app/backend/.venv/bin/python tools/pipeline_fault_drill.py

证据分三档，本表只用这三档说话：实测＝本日在真实代码路径上跑出来的输出；测试证据＝pytest 里钉住同一语义的用例；人工步骤＝要花钱、要真机或要真账单，平台不代跑、也不许伪造。

2.4 两个状态不是一回事

job.status=needs_attention 说的是作业需要人处理；billable_status=pending_reconciliation 说的是费用待核对。云端作业可以同时占这两个标记，也可以只占后者（比如回执成功但账单没核对）。演练 2、3 的输出把这条界线跑实了：挂待核对时费用快照不动，核对时实际金额单独入账。

现库事实（2026-11-02 只读盘点）：job 共 13 条（succeeded 11、failed 2）；其中 #37、#38、#39 三条云端文本作业 succeeded 且 pending_reconciliation——这正是评审说的"预估金额不能当实际费用"的活样本，要等人在 DeepSeek 后台对出真实账单后走核对，平台不自动消掉它们。

2.5 人工步骤（阻塞项，平台不代跑）

事项为什么必须人工解除条件
云端视频真调用演练花钱，每次调用要操作者确认预算与费用上限确认阿里云 Wan 档位后跑一条，登记 real_call
三笔云端文本账单核对（#37–#39）实际金额只存在于供应商后台，平台不猜DeepSeek 控制台对账 → 生成中心核对 → 登记 real_call
音频三运行时真调用运行时未装齐，装了才算VoxCPM2/ACE-Step/口型对齐装好并健康检查通过
M5 Ultra 目标机基准目标机未到货，查无记录就显示 UNKNOWN，不填推算值机器到货后跑 §1.2 八步＋目标机档验证
正式库上的完整恢复演练恢复进的是临时目录，正式恢复会覆盖 data/定维护窗口，备份→verify→restore --yes→重启验证
产线生成节点用真实模型跑通一镜本机没有图像／视频运行时，且真调用要花钱、要人确认预算运行时装好或云端档位确认后，用「视频生产」模板跑一条 run，再去审核中心产物页签签字
用真实模型生成的整集分镜做合成现有成片验收的视频是临时构造的测试素材；真实模型出片还要先解决运行时或付费按上一行跑出一条真实镜头，凑齐一集后走标准漫剧单集 v2，看观感、音画同步与编码兼容性
硬字幕的真实烧录验证本机 FFmpeg 9.0.2 没有 libass，ffmpeg -filters 里查不到 subtitles；测试只能走「提交前就拒」那一档换带 libass 的 FFmpeg 构建后跑一次「烧与不烧的 PSNR 对比」，测试会自动改走另一档
预检的磁盘阈值（5GB）是拍的默认值，没按目标机实际产物尺寸校过；实施文档明说并发与阈值要真机定M5 Ultra 到位后与 §7.6 基准一起标定
