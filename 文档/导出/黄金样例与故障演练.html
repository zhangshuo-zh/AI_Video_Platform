1. 黄金样例

1.1 样例包

每次发布后按这一套东西原样跑一遍，跑通了才算发布完成。内容是原创的微型故事，只有三镜，本地预览档几分钟内能跑完。

剧本（创作中心 → 文档，约 300 字，保存后记录 Git 版本号）：

> 《修伞匠》 > 雨下了三天。巷口的老人还坐在他的摊子后头，面前摆着三把断伞。 > 镜一：雨巷全景。青石板反着光，修伞摊缩在屋檐下，老人戴着老花镜低头理伞骨。 > 镜二：手部特写。粗糙的手指捏着细伞骨，铁丝在指间绕了两圈，收紧。 > 镜三：中景。少女把一把修好的伞递回来，老人接伞，抬头笑了一下。雨还在下。

资产（资产中心，2 项）：

资产类型说明
修伞老人角色参考图 1 张；一致性提示词：蓝布围裙、老花镜、灰白短发
雨巷场景参考图 1 张；一致性提示词：江南小巷、青石板、屋檐滴水

镜头表（创作中心 → 分镜，3 条，都关联上面两个资产）：

镜号景别生成档提示词要点
1全景本地预览（FastMetal 1.3B）雨巷、修伞摊、屋檐，参考图＝雨巷
2特写本地预览（FastMetal 1.3B）手部、伞骨、铁丝，参考图＝修伞老人
3中景本地预览（FastMetal 1.3B）递伞、接伞、笑，参考图＝修伞老人＋雨巷

1.2 八步执行手册

  1. 建项目与剧本：项目中心新建项目 → 创作中心建文档《修伞匠·剧本》，粘贴 1.1 的剧本并保存。记录文档版本（Git commit 号）。界面见《系统使用说明书》§4 与 §6.2。
  2. 抽取：创作页对该文档发起文本抽取 → 抽出候选后逐条看原文证据，人工确认。当前版本不会自动把抽取结果变成正式分镜，确认后仍要手工建镜头。界面见 §6.4。
  3. 建资产与镜头：资产中心建 2 项资产并传参考图 → 创作中心建 3 条镜头，关联资产。逐条检查提示词和参考图是否对得上。界面见 §5 与 §6.5。
  4. 提交生成：生成中心选本地预览档提交。提交前确认路由、参数快照、费用提示；本地不花钱，云端档必须逐次勾计费确认。界面见 §7。
  5. 查产物：作业抽屉看产物文件、大小、时长、分辨率与 sha256；确认产物挂在对的镜头上。看不过眼的进「验证记录」登记产物验收结论。界面见 §7 与 §3.1（五档出处与验收结论）。
  6. 音频：配音/音乐三个运行时（VoxCPM2、ACE-Step、口型对齐）装好之前，界面显示未验证就是未验证，不在样例里假装跑过。装好后这一步补真实调用。界面见 §9。
  7. 审核与导出：审核中心过 gate 报告 → 人工签字 → 项目看板导出镜头清单。界面见 §8 与 §11。
  8. 备份恢复：按 §2.3 的三条命令做一次备份 → 校验 → 恢复到临时目录，确认项目、文档 Git 历史、Job 和产物引用都还在。界面与命令见 §16。

1.3 验收标准

每个结果都要能一路追溯到：输入文档版本 → 镜头 → 资产 → 模型档 → 参数快照 → Job → 费用 → 审核结论。任何一步失败，要能说出失败发生在哪一步。八步全部留下记录，这套记录就是这次发布可以复现的证据。

2.4 两个状态不是一回事

job.status=needs_attention 说的是作业需要人处理；billable_status=pending_reconciliation 说的是费用待核对。云端作业可以同时占这两个标记，也可以只占后者（比如回执成功但账单没核对）。演练 2、3 的输出把这条界线跑实了：挂待核对时费用快照不动，核对时实际金额单独入账。

现库事实（2026-11-02 只读盘点）：job 共 13 条（succeeded 11、failed 2）；其中 #37、#38、#39 三条云端文本作业 succeeded 且 pending_reconciliation——这正是评审说的"预估金额不能当实际费用"的活样本，要等人在 DeepSeek 后台对出真实账单后走核对，平台不自动消掉它们。

脚本在 tools/pipeline_fault_drill.py，一条命令重放全部十条，同样是临时库＋mock 适配器，不碰真供应商、零付费：

演练用的模板是四条节点的缩小版：读项目 → 关键帧（按镜头展开，2 镜）→ 产物检查（按镜头展开）→ 验收（等签字）。故意比内置的 13 节点模板短，好让每一条演练的观测都能一眼看完。

#演练结论观测
1建了运行、还没推进过就崩通过重启后从库里的状态接着走：7 个节点一个没多一个没少，read_project=completed，关键帧节点当轮派出作业
2节点已就绪、作业还没提交就崩通过补提交且只提交一条：节点拿到 job_id，幂等键 pl-<run>-keyframe#s<镜头>-a1；连推两轮库里仍只有 1 条产线作业
3作业已落库、节点还没关联就崩通过按幂等键认回原作业，节点重新指向它，产线作业仍是 1 条；事件流里如实记了 reused=true
4作业跑一半 worker 被强制终止通过recover_stale 收成 failed(worker_lost)，节点跟着 failed，运行状态 failed；作业数没变——产线不自动重试
5作业已成功、节点还停在执行中通过按 Job 真相对齐：两格关键帧 running → completed，产物检查同轮做完，运行进 waiting_review
6一镜失败，只重试那一镜通过新作业 retry_of 指向旧行、attempt=2，旧行原样留着；好那一镜的作业与 retry_count=0 一个字段没动；项目作业 2 → 3，其中产线幂等键仍 2 条

2.7 产线页面真浏览器验收（阶段 C，实测 2026-11-03）

无头 Chrome 起 live API 与 live worker，用临时管理员与临时只读账号走真实登录；临时项目、临时集、剧本与一条镜头在脚本里建，跑完级联删除。样例用的是 §1.1 的修伞匠微故事（三句正文＋一镜雨巷全景）。

节验什么观测
0—1准备与入口临时项目建好、顶栏切过去；侧栏顺序 generate → pipeline → audio，产线中心在生成中心之后
2模板页签三份内置模板都在，写清只读、没有拖拽；标准模板展开 13 个节点
3发起运行弹窗模板下拉带版本与节点数；列表出现一条运行；一次 advance 都不调，live worker 的 tick() 把它推到 waiting_review；前五个内部检查完成，关键帧在等前置，详情画出 13 个节点
4暂停／恢复暂停后状态 paused；恢复后回到 waiting_review
5人工审核在审核中心跑 gate 并整份签字 → confirm_script 自己完成；关键帧因本机没有运行时以「图像的本地档还没填 provider/模型」失败，运行 failed

7同集第二条改一句正文，旧签字作废；上一条结束后允许再起一条；已有未结束运行的集在下拉里禁用；取消要确认；取消后等签字节点跟着取消
8只读账号能看运行与模板；推进／暂停／取消／重试四个动作都不显示；直接调发起接口 403
9截图与窄屏夜间／模板／白天三张截图；380px 横向溢出修前 154px、修后 0px
10清理临时项目级联删运行、节点与事件（残留 0）；临时账号删掉；全程无未捕获 JS 错误

这一轮撞出并修掉的三条收尾缺陷（都在 pytest 里有回归）：① 失败运行的下游节点永远 blocked，finished_at 落不下来，同一集此后一直 409——收尾判据改成「全部终态或剩余节点不可达」；② 已结束的运行点重试不会重新打开——重试事务里 reopen() 清空 finished_at；③ 取消运行会留下仍在等人的 human_gate，迟到的签字能把它收成完成——取消时一并收掉。另按审计 R1 给 jobs.cancelled() 补了 worker_id 归属守卫。

证据边界：页面验收全程零付费，生成节点在提交阶段就被拒（本机没有图像／视频运行时）。它证明的是页面行为、权限显隐与三条收尾规则，不是真实模型生产验证证据；截图在 文档/assets/v90-pipeline-*.png，脚本按包临时重建、不入库。
